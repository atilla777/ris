# Native-bug publication basis

Read only for a supplied native bug, before selecting Task/change or Documents.
The existence of a bug ID does not turn pre-execution documents into a fix.

## Fix implementation (Task/change)

Use advertised typed bug/ownership/blocker reads, full current report/criteria/
accepted decisions and the full historical notes execution-input snapshot, not
task-only feature APIs or mandatory formal spec/design files. Retrieve file-backed
reports at their exact published locator. Require the snapshot's project/tracker +
exact bug ID + marker in implementation/review evidence and read its complete text.
Compare current report/criteria/decisions with that basis before publication;
material drift returns affected change/review/evidence for targeted reassessment
before dependent push. Keep separate material-design acceptance and sufficient
current technical inputs; no plan, omission-decision, implementation report or
author TDD-history audit is required. Do not infer past TDD from missing history
or conceal known violations. Mixed fix/document changes retain these guards.
These gates converge into the main skill's one Git algorithm; fix-completion
belongs to the adapter separately after publication, never investigation disposition.

## Pre-execution design/documents (Documents)

Explicitly select Documents even with an exact bug ID. Read the full current
report/criteria/accepted constraints and authority plus the exact document candidate
and its separate acceptance where applicable. Require independent **document-subject**
review and applicable checks on the complete tree; no future execution-input
snapshot, fix implementation evidence or execution plan/omission decision is
required. Compare current report/criteria/decisions with the bound document basis;
material drift needs affected design/document reassessment before dependent push.
This exception cannot approve a fix or bypass separate material-design acceptance,
whole-tree review, permissions, integration or remote-publication gates.
