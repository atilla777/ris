# Bounded selection among existing features

Owned by show-plan; read when an epic-level recommendation or a caller such as
feature preparation needs existing candidates for a specified SDLC action. This
is a reusable read-only contribution, not a new skill or product planning method.
The caller supplies project/adapter context and requested action, retains dialogue,
permissions and transitions, and may consume just this contribution without a
whole-project tree. Apply show-plan's dependency/read/scope/zero-write rules.

Read the exact epic's outcome and complete all-state direct work, with content
needed to establish feature kind/identity and current state. Expand related
records/typed dependencies only for a material selection question. Do not infer
kind from membership alone or use native ready as a requirements oracle.

If actually empty, recommend preliminary graph planning. If demonstrably missing
coverage, recommend bounded replanning with evidence; do not invent candidates.
If goal/boundary is unclear, recommend its clarification. Read-only status/next
never runs these operations. An authorized caller may execute the separately
agreed operation, then reread verified existing records for selection.

For existing features assess availability for the **needed action**, not just
absence of native blockers. Read exact prerequisite IDs/content and their needed
accepted decisions/results. Apply installed specify-feature's owned
`references/stage-prerequisites.md` when that action depends on stage evidence.
Check acceptance artifacts/decisions only where needed, not the entire lifecycle
history for every tree row. Implementation-only dependencies do not by themselves
bar requirements work; actual/unknown requirements blockers bar the dependent
action until the specified contract is accepted, not until another feature closes.
Unknown native blocker scope never becomes implementation-only by default.

Prefer relevant started **own** work whose action is available; foreign work
requires coordination, never takeover or a substitute new feature. Among available
existing candidates use priority (P0 highest), then earlier creation time, then
exact ID. Unknown ordering values remain explicit, not fabricated. Started work
that cannot continue gets its exact diagnosis. Show independent simultaneously
available candidates as a parallel set; dependencies for a later action do not
force strict serialization now. Return one recommended next action for status
plus optional parallel candidates; a one-feature flow chooses one (ask when the
choice is materially ambiguous) without prohibiting others from parallel work.

If all are blocked, return concrete decisions/results/ownership gaps and their
exact IDs, not a new product graph. If prerequisite kind/evidence is unknown,
block only the dependent conclusion and retain independently supported choices.
Fresh-read selected candidate and material membership/blocker facts before final
recommendation. Return exact IDs, requested action, ranking/evidence/parallel set,
known limits and any needed human choice to the caller. No writes, new capabilities,
acceptance, claims or readiness grant.
