# Conditional feature-preparation claim admission

Read with `claim.md` only for an explicitly requested `feature-preparation` claim
of an explicitly confirmed feature, before admission or own-claim reuse.

This purpose uses the same native record's `assignee/in_progress`, not a second
execution claim, stage record or metadata registry. Determine purpose from the
authorized request and caller contract; do not require a new persisted purpose
field. Verify/reuse an existing own assignment through the same guards. This
authorizes preparation only; execution later checks its own authority/inputs and
all execution gates even if the actor and worktree remain the same.

Also require the caller's stage-prerequisite assessment from installed
specify-feature's owned `references/stage-prerequisites.md`. Verify readable
requirements prerequisites independently of native blocks; a missing needed
accepted decision blocks dependent preparation even with no active native edge.
The caller supplies actual content/decision evidence, not a ready flag; never
require whole-feature closure when its specified accepted contract suffices.

Require the caller's exact authorized preparation action and inspectable scope
evidence for **every** active directed blocker, matched to freshly read edge/
endpoints/content. The caller owns the substantive action/scope decision; verify
its evidence against actual tracker facts. Admit a fresh claim despite active
edges only when each is proved execution-only and does not prohibit that
preparation action. Unknown applicability, missing evidence or a real preparation
blocker blocks admission. Do not infer execution-only scope from a title, raw
status, null refs or caller's purpose alone. This exception does not authorize
execution, remove edges or waive ownership.

Apply `claim.md`'s native claim, independent post-claim checks and conflict rules.
If blockers/content changed, preparation proceeds only when every remaining active
blocker is freshly proved execution-only for this exact action. Otherwise report
the persisted partial claim and exact gap; do not bypass refusal or create a
second claim engine. A preparation claim is never implementation readiness.
