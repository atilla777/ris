# Reconcile before continuing

Read for repeat/resume, partial/uncertain effects or concurrent changes. Reestablish
target/current copy and relevant permissions; reread actual config, AGENTS,
documents/decisions, Git/tracker/tool/agent state and available owner receipts.
Check previous settings/content acceptance against exact versions/scope and current
inputs. A stale success marker or missing chat is not proof of a completed effect.
Use accessible decisions and actual files; no mandatory recovery journal/registry.

Separate confirmed saved/checked effects, unknown effects and missing actions.
Reuse unchanged applicable acceptance and checks; do not repeat a confirmed save
because read-back is pending, reinitialize an existing tracker or reinstall tools
blindly. Ask the affected existing owner to reconcile an uncertain operation
before retry. Keep IDs/addresses/commits and independent completed work. Do not
roll back foreign changes, invent earlier acceptance or rewrite all rules on rerun.

On concurrent content/path/permission changes stop the **affected** writes, compare
the current state with the accepted scope and return the material conflict to the
leading dialogue. Reassess dependent candidates/evidence; only material changes
need new content acceptance. No filesystem transaction, universal CAS, distributed
lock or whole-flow idempotence is promised by baseline/read-back checks.

After config or copy changes, freshly apply context for actual path/role provenance.
If optional publication was attempted, use its owner to independently reconcile
the exact local/remote commit before retry; a push error/read-back gap does not
authorize another blind push. Report `blocked|conflict|error` with exact persisted
effects, locators, unsaved parts, limits and missing operation, not fictitious
rollback/full readiness. Resume only that missing/inapplicable part of the same
agreed setup; automatic roadmap or product development is never recovery.
