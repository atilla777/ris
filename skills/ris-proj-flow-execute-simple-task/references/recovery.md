# Conditional recovery of the same assigned work

Read on resume, discovered prior/partial effects, interruption, timeout or an
ambiguous response before choosing a transition or retry. Reconcile read-only
first, then gate only the actual remaining effects through the same main route
and owners. This is no second execution engine or mandatory journal.

Establish the attributable request/decisions and exact project/repository/copy/
branch association from available evidence. Inspect actual Git HEAD, commits,
index/files/untracked work, unfinished operations, registrations, target remote
and relevant refs; distinguish ongoing execution from an interrupted one. If
tracking applies, use the selected adapter for exact identity/kind/content,
status/ownership, composition/blockers and result/close/publication facts. Load
the tracker resource only under its own trigger. An assignee, path, branch name,
old lease or “done” message alone does not prove ownership, result or permission.

Recover full request/constraints, separate material decisions, exact candidate,
check results/limits and independent review subject/launch provenance from
accessible session content or authorized saved evidence. No history is assumed
available to a new session; ask only for the missing essential input. Do not
invent acceptance, passing checks or review because no report file was required.
Missing/inapplicable independent review requires a fresh independent invocation.
Compare current inputs and whole snapshot to evidence; reuse unchanged compatible
results with reasons, rerun affected checks/review for changed parts under the
main route's whole-snapshot publication gate. Material drift returns the affected
decision, not an automatic full preparation restart.

Use the existing owner to reconcile each uncertain effect before repeating it:

- Preparation: inspect existing association/copy/claim/setup; reuse verified
  effects, never recreate a branch/worktree or rerun non-idempotent setup blindly.
- Git: the publication owner freshly checks the actual selected remote for the
  sent commit/tree and reachability. A local commit or timeout is not push proof.
  Confirmed publication is reused without recommit/redundant push; missing
  read-back gets that check, and unsent work keeps outgoing/review gates.
  In full mode reconcile primary-copy sync separately through the same publisher;
  pending sync is not remote failure or permission to replay push. Preserve an
  explicitly authorized remote-only boundary without claiming local currentness.
- Tracker: adapter reads distinguish saved result, exact closure and separately
  published history. Reconcile unknown create/update/close before retry. Reuse
  known ID/confirmed close; a closed own task pending publication receives only
  the remaining publication/read-back, without reopen or another close. Pass the
  known required/recovered revision and evidence to the adapter rather than
  replacing it with a newer local tip. Current project publication policy governs.

Return the first missing/inapplicable operation within the main route, proven
prerequisites, reusable evidence, unknown effects and exact remainder. Check
current rights, own claim/blockers and reviewer availability only for remaining
operations; completed implementation needs no implementation role. Conflicting
ownership, unresolved live execution or missing essential evidence stops dependent
effects with preserved work and a concrete cause, never a blind replay or rollback.
