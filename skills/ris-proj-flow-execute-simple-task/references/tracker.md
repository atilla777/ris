# Conditional task accounting and completion

Read only when the request supplies an existing ID or the selected project
requires task accounting. The flow owns admission and sufficiency; the selected
adapter owns bounded tracker operations and their guarantees, not Git publication.

## Admission before changes

1. Resolve the selected tasks adapter only as needed through context; load/apply
   it and verify actual selected project/workspace, capabilities and rights.
   Require supported exact typed reads, complete mandatory membership and directed
   blocker reads, needed claim and separate result/verified-close/publication
   operations. Unsupported operations block their dependent effects, without
   direct storage edits or a second adapter engine.
2. With a supplied ID, exact-read that target's full applicable content, real
   type/kind, accepted inputs/decisions and current constraints, status/assignee,
   complete children and typed directed blockers. Do not globally search merely
   to resolve a known ID or substitute another target. A structural parent does
   not itself imply feature identity; ordinary children retain their own contract.
   Feature-linked inputs retain full exact accepted versions and separate
   decisions; missing/malformed feature data never selects ordinary admission.
   A feature/container is not silently executed or accepted as an ordinary leaf.
   A registered bug keeps its investigation/report, design, execution-input
   versioned basis and fix-flow prerequisites; return missing prerequisites or the
   appropriate existing route to the caller, never downgrade it to fast ordinary
   work. This flow does not replace feature acceptance or bug execution contracts.
3. Without an ID but with mandatory project accounting, reconcile identity across
   the complete relevant all-status set before creation, including closed tasks
   and other parents. Apply the adapter's ordinary-task create/reconcile method
   using a stable project-scoped retry key and short sufficient attributable
   request, outcome/boundaries/criteria, accepted constraints and actual decisions.
   Preserve external exact source/acceptance refs when present; invent no URLs,
   spec/design files, feature block, surrogate ID or artificial parent. Read back
   the confirmed ID/content/kind and absence of collisions under the adapter's
   actual guarantees. Ambiguous/multiple matches stop creation for reconciliation.
   In RIS itself short Beads accounting remains mandatory, even for explicit fast.
4. Before execution obtain or confirm the authorized own claim through the
   adapter, with exact actor and confirmed task association (and copy association
   for versioned edits, not a fictitious local-only worktree). Resolve a new
   assignment's missing actor through that adapter's claim owner (explicit →
   applicable configured → verified current session ID) and forward it unchanged.
   Existing claim/copy continuation uses common's explicit-human authority and
   verified linkage through the adapter, without another takeover confirmation;
   fallback, name equality or lease alone never grants takeover. Independently
   check in-progress ownership, blockers and mandatory composition before each new
   mutation batch and dependent publication. Without that authority preserve foreign claims.
   Active blockers, unfinished mandatory children or lost ownership stop dependent
   effects. Closed targets use recovery/state reporting, never automatic reopen.
   A claim/lease/worktree is not general graph/content CAS. Apply current project
   native-write/concurrency rules and report unsupported required guarantees.

For Beads, ordinary request/result/verified-close specifics belong to its
`references/standalone.md`, with only the action resources it selects. Feature
and bug resources stay conditional on real kind. Adapter instructions own CLI,
concurrency, identity reconciliation and write/read-back algorithms.

## After verified applicable output channels: separate operations

- Recheck own criteria, mandatory composition/blockers and evidence applicability
  on the actual completed subject. Mixed work requires both its Git and local
  parts; partial own-result success cannot close the task. Separately authorized
  policy-required source maintenance debt retains its existing close/Dolt exception,
  not permission to omit this task's own required local targets. Apply the adapter's
  bounded result persistence: short remotely sufficient outcome, actual checks,
  applicable review provenance and limits, actual decisions/refs and channel facts.
  Git includes its verified published SHA/remote evidence; local-only includes exact
  actual targets, verified useful effect and availability/portability limits instead
  of an inapplicable Git SHA. No-change records the checked existing result, never
  a fictitious commit. Do not copy secrets or full local configuration into Beads.
  Ignored local reports cannot be required remote
  inputs. Preserve foreign fields and original acceptance addresses; read back.
  For saved review, retain only its local YAML address and round ID in Beads,
  never a verdict/findings duplicate. No report file is mandatory for fast;
  session-only review retains its sufficient provenance in the session. Inactive
  review requires neither approval nor a skip report; known adverse findings and
  applicable mandatory review still constrain completion. Local
  report access from another machine is not promised. The short work outcome,
  actual checks, applicable channel evidence and completion facts remain distinct
  tracker content. Dolt publishes tracker history, not local target files.
- Separately request **verified-work exact close** of this confirmed task, only
  after all required work/evidence and fresh native predicates pass. Use the
  adapter's normal close and independent read-back, never administrative close,
  force or status-update shortcuts. This operation closes only the selected task,
  not children/parents; the flow's separate ancestor tail follows publication.
- Separately apply the adapter's authorized tracker publication operation (Beads
  `dolt.publish` and its conditional resource). Follow the current project's
  shared-history scope/remote/direction and read-back policy, including permitted
  other agents' history where authorized. This flow adds no stricter private-ref,
  global-lock or whole-history audit policy and weakens no actual project gate.
  An installed adapter, local result/close or Git push does not prove publication.

Check each operation's actual outcome before advancing. Preserve partial effects;
an uncertain response activates recovery before any retry. Return result saved,
exact close verified and tracker publication/revision/read-back as distinct facts
with remaining operations. Confirmed close with pending publication is never
reopened or closed again.
