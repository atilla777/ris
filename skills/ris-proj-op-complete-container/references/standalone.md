Read only for verify or verify-and-close of an explicitly identified ordinary
task-container; administrative close uses the SKILL's bounded path. It is not an
ordinary leaf and is not inferred from missing feature JSON, its title or zero
children. Require the exact ID/kind, closing authority only for verify-and-close, own
accepted outcomes/criteria, mandatory composition and source selectors/versions/
separate decisions. Discover from the selected adapter's exact reads and links.
Preserve malformed/historical feature records; no migration or invented epic.

## Assess the accepted whole

Apply the SKILL's complete all-status recursive membership and directed blocker
checks. Reconcile every mandatory result with actual records and disposition;
missing required members or unexpected extras conflict. Cancellation requires
accepted scope disposition, never automatic success. Closed children alone do
not establish outcomes. Do not rewrite children, reparent, shrink scope or close
ancestors to make the assessment pass.

Read exact accepted content/decisions and actual integration evidence. Compare
applicability to current rules, contracts and integrated result; retain unchanged
pins/acceptance. Material changes return to the responsible content owner.
If common feature-like AC must hold on one integrated revision, actually apply
`ris-port-op-verify-feature` with complete AC, accepted requirements, sufficient
accepted design, architecture/contracts, documentation and check evidence on
that remote-backed revision. Inspect its criterion coverage and limits; diff
review is not integrated acceptance. Otherwise assess this bounded composition's
own outcomes against addressed evidence/revisions for each delivery; do not force
unrelated deliveries onto one SHA or require feature-record/1. Substantial design
needs independent acceptance where material, simple constraints need no artificial
design file. Record pass/fail/unverified with concrete evidence for every outcome.
The assessment must satisfy project independence requirements; an implementation
author's report cannot supply an independent gate.

For default verify return the unsaved criterion → observation/evidence →
fulfilled / unfulfilled / insufficient-data assessment and stop. Reuse applicable
evidence with its revision and currency checks. No tracker/report writes or
publication follow. A verdict is not new user acceptance.

## Verify-and-close: protected persistence and separate exact closure

Only this intent uses the following write branch, with authorized persistence.

Check the selected adapter's explicitly advertised tool-specific ordinary result
persistence and exact-close support and apply its owned resource. `tasks` v1 and
feature-record/1 alone do not promise ordinary-container writes. Supply only
authorized fields, exact expected identity/content/composition, accepted refs/
decisions, outcome verdicts, integrated revisions, actual checks/independent
assessment provenance, usable evidence addresses and limits. Evidence must be
recoverable without ignored local reports. Prefer native append/independent-key
updates and fresh expected-content checks for replacement. Snapshot-dependent
evidence needs current applicability checks; a row merge/claim/read-back is not
graph/evidence CAS and does not promise such protection.

Before persistence and again before close freshly inspect content, full mandatory
descendants, cancellations, blockers and external-evidence currency. Establish
the adapter's applicable native guards and honest limits. Native close checks
direct children/blockers only; mandatory existence, expected composition and
external acceptance are substantively checked, not frozen through read-back.
No manual window, mandatory global lock or graph-wide transaction is required.
Unsupported explicitly requested stronger guarantees return an exact limitation,
preserving useful read-only assessment.

Persist the authorized assessment, verify exact read-back and preserved content,
then separately close **only this ID** when all mandatory outcomes/checks pass,
scope is complete, blockers absent and evidence remains applicable. Failure or
unverified evidence never authorizes close (failed evidence may be persisted if authorized).
Never force/recurse or use child status changes as a workaround. If already closed,
check scope/evidence and report unchanged; remaining publication/read-back never
reopens/recloses it. Ambiguous writes are reconciled by the same adapter before
retrying only proven missing effects. Use the SKILL's separate publication/result
contract; Git is an input and Dolt publication is independently verified.
