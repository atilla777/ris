# Investigate a registered bug

Own the combined investigation, discoverable current report, aligned criteria and
justified message disposition. Apply `ris-port-op-investigate-bug` for diagnosis;
this wrapper owns project inputs, authority, persistence and outcome verification.
The pair is useful because diagnosis also works independently of a tracker.
Do not implement a fix, create stage children/feature records or start execution.

## Prepare and reconcile

On direct invocation ensure `ris-proj-lib-common` is available through the host
loader or its actual installed location and apply it. Read its artifacts resource
before preparing content/handoff, quality before checks/conclusions, and dialogue
before questions. Ensure `ris-proj-op-resolve-context` and its owned configuration
resource are available and apply them to the selected project for applicable
rules and `adapters.tasks` selection/options, unless a current checked result is
supplied. Read applicable rules and relevant source contracts. No execution role
or shared workspace path is required for ordinary investigation; resolve shared
paths only if authorized supporting materials actually need them. Do not require
spec/design files or product inputs irrelevant to this bug.

Require the exact bug ID, project, allowed research and tracker write scope. Through
the selected available adapter exact-read expected native type `bug`, original
message/supplements, current report/criteria, decisions, status and relevant links.
Missing/foreign ID or wrong type blocks this invocation, never implicit create or
conversion. Load and apply `ris-port-op-investigate-bug` with prepared substantive
inputs and project constraints. Missing dependencies block their contribution;
retain independently useful findings without claiming the whole operation saved.

Before dependent writes require the adapter's advertised ordinary bug report and
acceptance persistence, duplicate supplementation/relation and disposition-close
capabilities as applicable, with their actual guarantees. For Beads apply
`ris-proj-adapter-beads-tasks` and its owned `references/standalone.md`,
`references/investigation.md` and `references/concurrency.md` under their read
conditions. A CLI command or config selection alone is not capability support.
Pass exact expected IDs/types, authorized fields/content, report identity/version,
investigator, inspected code revision, agreed criteria, preserved sections and
requested effects. The adapter owns mechanics/protection/read-back; this operation
owns substantive conclusions and verifies the combined result. Use sandbox writes.

On continuation reconcile the existing current report and criteria plus any
original supplement, relation, close reason and publication evidence before
repeating research or writes. Reuse applicable findings/settled effects. A closed
input is not reopened: verify its disposition and return unchanged or an exact
conflict/remainder. Materially changed evidence or criteria needs reassessment;
do not silently keep dependent conclusions current or overwrite another author.

## Apply the method and establish the current report

Prepare inputs from the message and actually accessible pinned sources/code,
reusing known context without a repeated interview. Apply the portable method,
then check its report against those sources, authority, project rules and scope.
Keep confirmation and readiness separately explicit. Research readiness does not
accept requirements, grant fix authority or resolve a substantial design choice.
Return disputed expectation, stale/conflicting sources or shared-contract changes
to the specific authorized owner before dependent work; retain independent facts.

Default to one clearly delimited **current investigation** section in the bug's
description, separate from the original message and foreign sections. Give it a
stable identity scoped to project/bug, an unambiguous version, investigator and
inspected code revision. Map the portable report's full content/conclusions into
that section; reflect agreed fix criteria in acceptance, preserving unrelated
criteria/decisions. Unknown/unagreed criteria remain explicit gaps, never silently
accepted new product behavior. Keep historical notes as supporting evidence only.
Ambiguous/multiple current sections or conflicting versions require reconciliation.

Require real protection of the modified description and acceptance content,
including preserved original/foreign text. Baseline Beads 1.3.1 has no general
content CAS: claim, status/assignee guards, sandbox and fresh read-back are not
substitutes. The adapter must inspect actual supported protection; unavailable
protection blocks replacement, not independent research. Do not invent locks,
upgrade the tool, request a writer pause or downgrade the guarantee. Return the
unsaved report and precise persistence limitation; notes-only storage cannot be
called a saved current report. Verify report and criteria separately after writes;
a partial pair is not ready for use. Reconcile both before any retry.

When project rules require a separate document, use an agreed path ending in
`investigation.md` as the sole full current report, not ignored local notes. Use
the existing Git publication owner `ris-proj-op-publish-task` only with applicable
authorization, document checks and required independent review, and verify its
exact published revision/path receipt. Without those gates return the file's
actual draft/local/publication remainder. Save only a summary and exact published
Git locator in the bug, under the same content-protection gate; retain aligned
acceptance. Verify retrieval at that revision from the bug. Do not keep a competing
full current description copy, delete historical content or claim publication from
a local file. Reconcile any existing full report explicitly before changing storage.

## Check the outcome and stop

| Evidence-based outcome | Required result |
|---|---|
| Confirmed, insufficient for a fix | Keep open, save findings and exact remaining gap. |
| Confirmed, sufficient for a fix | Save sufficient report/criteria only; do not start fixing. |
| Insufficient evidence to confirm | Keep open and unconfirmed, record observations and bounded next step. |
| Proved correct behavior | Save correctness rationale, then separately close this message as not a bug. |
| Proved duplicate | Save proof/original ID, preserve useful delta in original, verify relation, then separately close this duplicate. |

Insufficient data, unknown cause and failed reproduction never justify closure.
Investigation authority includes disposition of proved not-bug/duplicate messages
without a redundant confirmation, subject to project permissions and native gates.
For duplicates exact-read the original's actual type/status and preserve its
message, foreign content and feature payload. Native bug and explicitly permitted
legacy ordinary task originals may receive a stable scoped useful-information
supplement; never convert their type, reopen them or close the original. Verify
the supplement or a justified no-useful-delta finding, explicit readable duplicate
meaning/original ID, and the supported nonblocking typed duplicate → original
relation before close. Similarity alone cannot select this branch.

Ask the adapter for separate exact disposition-close only after stored rationale
and all required preceding effects are confirmed. Check complete children/blockers
and no-force native close/read-back. Native refusal stays blocked. Disposition is
message resolution, not fictitious satisfaction of fix acceptance or publication
of a nonexistent fix; ordinary task/feature completion keeps its existing gates.
On any failure stop remaining writes; return report, acceptance, original append,
relation and close effects individually. Never blindly replay the chain.

Inspect independent read-back of exact ID/type, report identity/content/version,
investigator/code revision, acceptance, preserved original/foreign content and
status. For file storage check the exact retrievable Git locator; for disposition
also check original ID/supplement, typed edge direction and persisted close reason.
Unexpected changes are conflict, ambiguous effects remain unknown pending reads.

Return `status: ok|blocked|conflict|error`, project/config/current-copy provenance,
tracker address plus ID/type, report locator/version and source/evidence versions,
confirmation and readiness with reasons, accepted constraints versus proposals,
checks/limits, each actual saved/unchanged/partial effect and exact remainder.
`ok` means the requested investigation effects were saved and checked, not a fix
or its acceptance. Distinguish local tracker persistence, file Git publication,
exact message closure and separately authorized tracker publication; the latter
uses the selected adapter's publication contract and is never implicit. Stop at
the checked investigation result; do not select/name or start the next skill.
