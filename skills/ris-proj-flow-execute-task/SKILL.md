description: >-
  Execute one ready RIS task through preparation, implementation, independent
  review, verified Git publication, separate completion and tracker publication.
  Use for a full task run or safe resume with an explicit ID or automatic
  ready-task choice, or an exact native bug with sufficient versioned inputs;
  not for selection alone, planning, review, publication alone, feature preparation
  or executing a whole container. Resume reconciles actual effects and reuses
  applicable results through the same stage owners.

# Execute one ready task

Before dependent feature/child execution apply installed specify-feature's owned
`references/stage-prerequisites.md`: inspect actual parent-feature requirements
prerequisites, implementation results and directed blockers as well as the child's.
Do not infer feature kind from membership, duplicate edges or bypass native refusal.
No-ID native ready is only candidate discovery, never a requirements/readiness oracle.
Ordinary and native bug routes retain their contracts and strict execution guards.

Own selection, transitions, one human dialogue and the sufficiency of the combined
result. This is one project scenario, without a new portable base: component
skills already own the portable stage methods. The tracker owns identity, status,
assignment, membership and blockers; Git owns content versions. Local reports
are evidence, never a second queue. Do not run multiple tasks, prepare unaccepted
requirements/design, integrate Beads formulas, create a workflow engine, migrate
historical records, repair/remove worktrees, deploy, release or substitute a PR.

## Prepare scope and executors before effects

Establish the selected project/current copy and context-checked ordinary source
folder association for shared paths, optional exact task ID, actor, accepted scope, applicable
rules and permissions. Load/apply installed `ris-proj-lib-common` and its conditional
resources before their actions; apply `ris-proj-op-resolve-context` with its owned configuration
resource to prepare sources, needed workspace paths, selected tasks adapter and
roles only for operations actually delegated:

| Configured role | Standalone operations |
|---|---|
| `task-execution` | Queue/readiness investigation, copy/claim preparation, Git publication, completion, tracker publication and fresh next recommendation |
| `task-implementation` | Code/text implementation and repairs |
| `task-review` | Independent review and integrated-snapshot reassessment |

Check the independent review role and any actually delegated role's mapping and
host availability/permissions before dependent effects. For recovery first reconcile read-only, then gate only
roles and permissions needed by the remaining route; completed implementation or
review does not require launching its role again. Reassess the gate if the remainder
changes. One agent name may serve all roles, but review uses a **fresh invocation**
independent of every implementation/repair author. Missing/unavailable roles block
the dependent delegated route; no silent fallback or model switch. The leading
agent may directly apply bounded operation owners, except independent review.
Role configuration alone proves neither model, invocation, independence nor
Advanced implementation; verify actual executor/model evidence for such claims.
Do not require feature-preparation/decomposition roles for this task route.

The request for a full run authorizes the agreed single-task cycle, working
artifacts, publication and completion subject to higher-priority/project limits.
Check actual permissions for file edits, claim, Git commit/direct push, exact-ID
completion and **all outgoing tracker history**. Do not infer acceptance from
workflow permission. Let the selected adapter establish operation-specific
guarantees: use fresh reads, targeted native atomic/conditional operations and
read-back, and shared-history tracker publication with remote revision assurance.
Ordinary work needs no manual window, mandatory global lock or graph/external-evidence transaction.
A claim, lease, sandbox or worktree is not general content/graph CAS. Apply
read-only preflight through the selected adapter and Git publication owner for actual
capabilities, destination/ref, outgoing scope, restrictions and remote read-back.
Missing guarantees block only dependent effects; preserve usable results.

Resolve a missing actor for a new assignment through the selected adapter's claim
owner (explicit → applicable configured → verified current session ID), then
forward that exact actor to participants. Existing execution recovery verifies
assignment/copy linkage and uses common's explicit-human continuation authority
through the adapter; do not ask again solely for a different previous actor or
preparation claim. Actor fallback/name/lease alone is not authority. Full execution uses
its own branch and separate working copy, never simultaneous independent writers
in one copy; simple-task uses the same worktree-first preparer and retains only
its scoped preparation/reporting exceptions.

Apply each bounded operation's owner directly or actually launch the configured
subagent when delegating it. Reuse suitable implementation/repair context; always
launch independent review separately from all authors/repairers. Do not split internal
reads into agents or load all child methods merely to route them. Within this
session pass only missing facts. For delegation apply common's artifacts handoff:
bounded goal/scope, project+ID and checked copy/actor, exact accessible inputs/
decisions, permissions and expected result. Context owns shared-path resolution;
do not repeat primary-root provenance in every transfer.
The recipient loads/applies its owner and dependencies and returns choices here
instead of interviewing the user or accepting unseen content.

Bound each handoff by a checkable intermediate result and early-return conditions:
an accepted-contract/platform conflict, unavailable essential evidence, or a check
that needs materially more setup or external access than planned. Ordinary
instruction edits use reading, applicable static checks and independent review;
absence of a new live run is not an evidence blocker or a reason to ask again about
one. Apply the target project's prohibitions and permissions. Static source
readiness does not establish observed agent behavior; preserve historical evidence
versions, limits and unmet obligations without importing their gates into an
ordinary text edit. An explicitly accepted behavioral objective needs separately
agreed scope under project rules.
The recipient returns preserved effects, affected criteria and the necessary
decision promptly; it does not bury the issue in a long implementation/evaluation
loop. Continue only independently useful authorized work. Give concise accepted
input/version references and relevant prior evidence, not the entire accumulated
history; recipients still read their applicable rules and owner resources.

Consume the owner's exact result/locator and material effects, limits and
remainder, not a mandatory handoff field set. Common's artifacts resource owns
fact sources and recovery; no envelope, file or registry is introduced.

Before each transition verify actual executor/provenance (including launch when delegated), accessible exact results
and current prerequisites from live Git/adapter facts and published input versions;
unsupported “done” is insufficient. Bind checks/review to the complete candidate
(base plus all additions/deletions/modes), inputs and independent reviewer; unknown
snapshot, review independence or task/copy association blocks only its dependent
step. Forward only missing verified inputs; mutable rights/claim/blocker/copy
facts are checked by their receiving owners, not inherited from an old handoff.

Do not require `worktree.md`, `execution.md` or an equivalent file/Beads transition
journal, or a persisted entry for each handoff. No saved plan, implementation
report, omission-decision or replacement log is required. Preserve independent
review and sufficient tracker result without distributing the removed report's
fields into them. Existing plans/journals are optional hints,
not authoritative or mandatory inputs; their absence alone is not a blocker.
Read `references/evidence.md` only for recovery or insufficient/conflicting
transition proof. For own unfinished work, previous/partial effects, an interrupted
operation or closed pending-publication work, also read/apply
`references/recovery.md` before selecting a transition/retry. An ordinary fresh
run loads neither detailed resource merely for its first handoff/report.
Nonstandard association, non-idempotent setup, remaining processes or ambiguous
partial effects require a compact addressable result in an already authorized
channel before a dependent irreversible action; if unavailable, name that exact
gap and block that action. Do not introduce a replacement journal or registry.

## Select exactly one target

Apply the necessary exact-ID or queue reads below and relevant epic/typed-edge
reads to the selected adapter. It must advertise actual complete item/child/dependency reads,
ordinary source/content reads where needed, tool-specific claim/complete and separately
verified tracker publication; `tasks` v1 alone does not promise all of these.
Automatic selection remains task-only; never search/select bugs as queue candidates.
An explicit native bug uses the adapter's advertised ordinary typed bug reads,
claim, historical basis read/locator and result persistence and separate fix-completion, not task-only
feature APIs. For Beads apply its conditional `references/bug-execution.md` before
these operations. Missing ordinary support blocks that branch without conversion.

With an explicit ID, reread that **target** and necessary relationships/content
for execution; no global list is required merely to resolve a known ID. Queue
reads need an actual diagnosis/recommendation or absence/dedup purpose. Never
replace the target. A closed ID gets a verified
state/result report, never reopening or a new implementation; proven own pending
publication resumes only its remaining verification/publication. An explicit
human execution/continuation request authorizes the adapter's guarded reassignment
of a previous session's claim under common; without that authority preserve it.
Unknown IDs/types return a concrete diagnostic.

Without an ID, obtain the complete relevant all-state task inventory through the
adapter's compact read policy, disclosing content needed for selection/readiness.
First identify confirmed own unfinished executions: actor supplied
explicitly or recovered from verified execution evidence, matching tracker
assignment, task/execution/copy linkage and no contradictory live execution.
OS user, issue `owner`, branch name or assignee alone does not prove ownership.
Uncertain ownership needs one necessary user decision, not silent bypass.
A closed task with proven pending tracker publication can be own unfinished work.

Sort confirmed own work first; otherwise sort ready candidates by tracker
priority, creation timestamp, then stable lexicographic ID. Beads lower numeric
priority wins; another adapter must supply unambiguous semantics. Compare parsed
timestamps, not locale strings; incomplete ordering data needs clarification.
If selected own work is blocked, stop on it instead of selecting a new task.
Route prior effects through the conditional recovery resource; **do not restart
from preparation** or skip blocked own work to choose another task.

## Verify readiness

For the chosen ID, check agreed outcome/scope/criteria, accepted applicable design
or sufficient accepted technical constraints for a standalone task, essential
inputs and current contracts, status, ownership, typed directed blockers and
complete mandatory composition. Implementation proceeds directly from sufficient
accepted inputs/current code; missing plans/reports do not create a stage or gate.
Successful decomposition or task existence is not execution readiness or authority.
Defined future prerequisites may have allowed task creation, but needed results
must now be integrated/applicable and active or unresolved execution blockers
stop dependent execution, even with an existing own claim. Preserve necessary
directed blocks and native refusal; permission to plan/decompose is not permission
to implement.
For feature-linked work apply common's published-inputs document convention and
bounded legacy discovery to actual published requirements/design and separate
attributable decisions. Missing actual accepted inputs is a preparation gap;
missing/old/malformed JSON alone is not. No epic is fabricated for a root feature.
Check exact versions and current applicability without repinning unchanged
acceptance, registry writes or migration. Membership is not a `blocks` edge; evaluate parent restrictions
under project rules without inventing an edge.

Discover these inputs from exact selected-adapter ID reads and linked versions,
not a mandatory caller questionnaire. Explicit ordinary standalone leaf/child
uses its own sufficient contract and accepted sources/constraints; structural
parent need not be an epic or feature. A child is not feature-linked merely
because it has a parent. Confirm actual kind from explicit scope/content/source
association, not JSON or parent-child alone; preserve historical payloads unchanged.

For an exact native bug discover its full current report (description or exact
published file), aligned criteria, accepted constraints/decisions and reproducible
versioned execution basis through the selected adapter. Require expected behavior with authority,
confirmed divergence/applicable code/environment evidence, authorized bounded scope,
meaningful fix/regression checks and sufficient technical constraints. Readiness
alone is neither acceptance nor authority. The sufficient report replaces formal
spec/design; a material technical choice still needs separately accepted design.
Missing inputs/decisions return a precise gap, not silent investigation or feature
preparation. Before fresh execution require adapter-verified exact historical
report/criteria/decision content and an accessible versioned-basis locator from
project/tracker + exact ID, with used immutable Git sources/decisions and inspected
code/environment. The adapter owns complete historical reads and ordinary locator
append/reconcile. Missing/incomplete history is a precise preparation gap; do not
substitute current HEAD. No full notes snapshot, copied text handoff or new file is
required. Preserve old full snapshots as usable historical inputs without migration.
Unsaved material decisions go to their existing owner before dependent execution.
At transitions/resume compare current report/criteria/decisions with this basis;
material drift requires targeted assessment by affected change/review/evidence
owners before dependent effects. Preserve compatible evidence with reasons and
existing published/closed effects. Do not treat parent membership as feature identity.

A container with unfinished mandatory children is not executable as one task:
report its boundary and recommend a ready child without claiming/starting it.
Do not execute a multi-task container even when its children are closed; container
completion is a separate request. An independently confirmed one-task feature
with no decomposed mandatory children may use the full-feature route below.
No ready candidate means explain specific gaps and recommend a preparation step,
without starting requirements/design acceptance. Announce chosen ID and basis;
continue without formal reconfirmation of already accepted inputs.

## Execution sequence: fresh work or reconciled remainder

Fresh work starts at step 1. Recovery returns the first missing or inapplicable
operation, its proven prerequisites and exact remainder to this same sequence.
Enter the identified operation within a step, not the whole step blindly. The
leading scenario authorizes each transition after inspecting the owner's receipt;
owners retain their full methods. Reconcile again after partial/uncertain effects
or changed facts before deciding the next operation.

1. Apply `ris-proj-op-prepare-task-worktree` with exact task, actor, permitted claim,
   copy/environment actions and applicable context. Check its verified claim,
   blockers, copy association, proportionate preservation observations/limits
   (ordinary new create versus reuse or hooks/setup) and separate copy/environment
   readiness. Use its actual handoff, not
   a guessed branch/path. Refresh context after a copy change. Retain the
   verified work/copy association when needed by the recipient; it never replaces
   fresh permission/ownership/blocker/protection gates at the receiving stage.
   If the caller already prepared this native bug's copy for necessary design,
   pass its exact checked ID/repository/path/branch association and actual effects
   to this same preparation owner for reuse, now with the sufficient accepted
   execution basis and readable pinned historical inputs. Verify the same association
   against live state; mismatch or unavailable association evidence blocks the
   dependent step, not permission to choose a second copy. Reconcile partial
   copy/setup effects before retry without replaying creation or completed setup.
2. Recheck actor ownership and blockers before each new change batch. Apply
   code behavior (including mixed code/text) to `ris-proj-op-implement-task-tdd`;
   apply its base method by actual slice, not the task's name. Behavior-changing
   slices require observed expected RED before the corresponding production edit
   and GREEN afterwards; environment errors are not RED. Pure behavior-preserving
   refactors may remain GREEN without artificial RED, with sufficient applicable
   existing/characterization and affected regression/static checks under that method.
   Mixed work retains the behavioral gate for every behavior-changing slice;
   unknown scope is not refactor-only. Require affected checks and the exact
   code/tests/authorized-docs snapshot. The implementation owner checks current-input
   sufficiency and chooses a viable approach in current code; material gaps return
   to this dialogue, not silent redesign or a planner. For text-only work read `references/text-work.md` and apply
   its bounded content owner without artificial RED. Check actual artifacts and
   criterion coverage; author evidence is not independent approval.
3. Launch a fresh `task-review` subagent applying `ris-proj-op-review-task` to the exact full
   candidate snapshot, requirements/design or sufficient versioned bug basis and
   separately accepted decisions, project rules and check evidence.
   Pass publication-gate purpose; require one saved local `review.yaml` and explicit round ID under the installed
   `ris-proj-op-review-task/references/report-format.md`; read/apply that owner
   before consuming review. Apply its consumer gate with current work/purpose,
   full tree/base/exclusions, accepted inputs, required checks and actual launch/
   all-author evidence; require applicable external approval, not just a verdict.
   Review assesses final results, not author RED/GREEN history
   or implementation-report discovery. No implementation report or author cycle-history audit
   is introduced at execution/recovery/publication.
4. High/medium findings go back to the implementation owner for fixes, affected
   checks and a new independent review. Record low dispositions collectively or
   individually; low alone does not trigger repair, a new task or a new round.
   Changed snapshots need applicable review. Compare rounds by resolved causes,
   new verified facts and remaining mandatory findings. Repetition without a
   justified new approach needs cause diagnosis; if no viable progress, preserve
   actual effects, stopping cause and exact remainder with the cause's
   `blocked|conflict|error`, or ask the necessary question. There is no fixed round cap.
   Use the explicit machine verdict: valid applicable independent `approved`
   ends the loop; `changes_required` repairs/re-reviews; `blocked`, missing,
   invalid/unsupported or inapplicable evidence stops dependent progression for
   the exact missing fact, never an endless implementation loop. No fallback
   past later adverse/unknown evidence to old approval.
5. Apply `ris-proj-op-publish-task` with exact approved full snapshot, independence
   evidence and authorized primary branch/remote. Never stage foreign paths,
   reset/stash their work, bypass hooks or force push. Consume the publisher's
   integration/reconciliation result; a changed candidate returns for affected
   checks and fresh independent `task-review` reassessment **before push**, never
   self-approval. The publisher owns ambiguous remote-effect recovery.
   Direct-push prohibition blocks this route without PR fallback.
   Record actual integrated commit/ref and independent remote visibility evidence.
   Check applicable accepted project policy for local maintenance and pass its
   actual source/version/acceptance and boundaries, or the explicit request, to
   the publisher. Without either, consume its remote-only default. Either source
   can activate separately reported source-copy safe FF, never branch switching;
   dependency refresh needs its own bounded authorization. Skipped/failed local
   synchronization never blocks independent criterion verification, exact close
   or Dolt publication. A policy-required or explicitly requested local update
   remains unfinished in the combined result; recover only that local
   effect through the publisher, never repeat confirmed push.
6. Only after confirmed Git publication, verify criteria and mandatory scope on
   the published version. For a leaf task, apply selected-adapter bounded
   result persistence and separate native exact-ID completion (advertised tool-specific
   ordinary operations for standalone tasks or native bug fix-completion, not
   investigation disposition or feature-record/2) with criterion/check/review
   evidence and published commit. In tracker review references store only the local
   YAML address and round ID, not copied verdict/findings; short work result,
   checks, published SHA and completion facts remain remotely sufficient. Local
   reports are not promised available on another machine. Require fresh status, complete child/blocker
   reads, fresh applicable external evidence/mandatory composition and honest
   predicate-specific native limits, without freezing graph/evidence. No future
   `ris-complete-task` dependency is required. For a selected one-task feature,
   apply `ris-proj-op-complete-container` with explicit **verify-and-close**
   intent for **all** feature AC, integrated revision,
   current substantive assessment and exact closure without mandatory saved
   feature verification or duplicate refs. Diff review or closed
   children cannot substitute for feature acceptance. Never close parents.
7. Apply **separate** selected-adapter tracker publication with authorized shared-
   history scope, selected destination and local result/records/typed-link evidence;
   for prior/ambiguous effects pass the exact requested/recoverable revision and
   available evidence. The adapter owns historical recovery, remote reconciliation, non-force
   publication and reachability verification (Beads: its conditional
   `references/dolt-publication.md`). Require its fresh remote confirmation of
   that revision; unknown revision/read failure remains unverified. A newer remote
   never justifies replaying confirmed effects. Git push, local result/closure
   and tracker publication remain three separate facts.

Stop dependent effects on an ambiguous or failed operation, including timeout or
lost executor response. Apply the recovery resource with the corresponding owner
to inspect actual state and live execution before retry. Save partial effects and
the exact remainder; continue only when reconciliation and the remaining gates
permit it. Do not replay an effect to manufacture success.

For a confirmed contract conflict or materially growing verification effort,
surface the concrete decision in this dialogue before commissioning more dependent
experiments. Do not commission agent tests prohibited by the target project or
make live evaluation an implicit stage of ordinary instruction repair. Reuse
applicable observations within their original limits, checks for unchanged
mechanisms, and rerun affected static/program checks. A mandatory
check cannot be silently dropped: obtain acceptance of any scope/verification
revision and record unrun checks and remaining limits, never a fabricated pass.

## Assess and report

Apply fresh read-only queue/readiness assessment for the next recommendation,
using the same ordering and readiness rules. Recommend one ready task with its
basis or a concrete preparation step. Do not claim or start it and do not switch
to it when the current target is blocked.

Return `ok|blocked|conflict|error`, ID/title, what was done and the user-visible
change (or explicitly internal-only), checks/review and their applicability,
project/config/actor/copy, component/evidence addresses, published Git commit/ref,
separate closure and tracker snapshot/read-back facts, limitations and next
recommendation. On a stop include the cause, preserved actual effects, first
remaining operation and required recovery/decision. `ok` requires all promised
effects verified for the selected task; never infer it from one channel or an
executor's assertion. Distinguish reused results, reconstructed observations,
new operations and invalidated/unverified evidence in a resumed report.
