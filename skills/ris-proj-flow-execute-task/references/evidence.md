# Execution evidence and applicability

Read only for recovery or insufficient/conflicting transition proof. Apply
common's `references/artifacts.md` for fact producers, consumers, mutable sources
and recovery; do not create a second receipt schema or transition ledger here.
Project+exact ID and Git/config/tracker sources discover saved results without
the prior chat, final response or ignored notes. No plan/implementation report is
an admission input. Local evidence has no automatic remote-availability promise.

For the proposed transition identify the existing effect, its accessible exact
source and whether evidence applies **now**. Inspect only the necessary facts:

- Accepted own contract and separate decisions through common's published-input
  method; parent membership alone is not feature identity. For a native bug ask
  the adapter for full used fields at the versioned basis and read its immutable
  Git sources/decisions, not a hash-only or copied snapshot handoff.
- Current assignment/continuation authority and blockers through the adapter;
  current copy association/state and any setup/process uncertainty through the
  preparer. Context owns paths. No branch name, expired lease or old receipt
  substitutes for these mutable facts. Shared refs/Beads are not worktree-isolated.
- Actual candidate and affected check observations/limits through the change
  owner. Compare exact content/inputs, including additions/deletions/modes and
  declared foreign exclusions, not HEAD alone. Material tree/basis/rule changes
  require affected-owner applicability assessment, not automatic full restart.
- Review address/round through the installed review owner's
  `references/report-format.md`: consume its format and external-approval gate,
  including actual invocation/all-author independence and later evidence. No
  copied verdict, success assertion or historical RED/GREEN audit replaces it.
- Git publication through `ris-proj-op-publish-task`; result/exact closure and
  tracker publication separately through the adapter. Inspect exact returned
  revision/remote confirmation and limits. Neither local status nor another
  channel's success proves remote availability.

Keep usable evidence at its existing address; forward only the missing locators,
versions, permissions, effects/uncertainty and expected bounded result. Do not
require run metadata or receipts for every prior transition. Actual delegation
provenance is required where independence or a claimed executor depends on it.

Missing review is restored exactly or replaced by a new independent review of
the available exact subject with current time/provenance, under its owner. If the
old tree is unavailable, name the current subject honestly; never infer historical
approval before a former push. Rerun lost reproducible affected checks. Find an
original acceptance decision or return only the lost material scope for new human
acceptance. Unknown setup, live process or ownership blocks dependent mutation.
Never fabricate old check/TDD/acceptance/independence facts.

For partial effects apply `recovery.md` to select only the missing operation.
Restored evidence describes its actual time/version; confirmed publication and
closed status stay facts even when historical evidence cannot be recovered.
