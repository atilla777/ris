# Execution evidence and applicability

Read only for recovery or insufficient/conflicting proof of a transition, not
before every ordinary handoff/report. Resolve resources from the installed skill;
authorized report paths come from checked project context and confirmed ID.

## Preserve identified observations

Use live Git/adapter facts, published versions and accessible exact operation
results. No `execution.md`, `worktree.md` or equivalent file/Beads transition ledger
is required; a missing journal alone cannot block. No saved plan, omission-decision,
implementation report or substitute/distributed log is required. Independent review
and sufficient tracker result remain. Existing notes may guide discovery but do not prove
current state. Inspect only facts needed for the dependent transition below;
this is a proof checklist, not a demand to write all fields after every operation.
When an authorized result/note needs updating, read it first, preserve history and
unrelated content, and verify the saved result. Otherwise return/forward the exact
result with provenance and explicit discovery gaps:

- Run identity/time, exact ID/title, actor and task/actor/execution association;
  project/current/primary roots, config source and resolved output addresses;
  context's checked Git-derived source-folder association and verification/limits.
- Requirements/design versions and acceptance addresses; applicable rule/package
  versions and material uncommitted changes to those inputs.
- Explicit kind and own leaf/child contract with exact accepted source selectors
  and decisions; sufficient standalone constraints where a design is unnecessary.
  Parent membership and feature identity are distinct. Record ordinary adapter
  capabilities/guarantees rather than inventing feature-record evidence.
- For native bugs: exact current-report source/version (retrieve full published
   file when used), exact tracker-history basis version and used Git source/decision
   locators, aligned criteria and accepted decisions/constraints. Through the adapter
   retrieve the full used historical fields; implementation/review identify that
   reproducible basis, not just a hash or copied full notes snapshot. Preserve legacy
   snapshots without migration; missing/incomplete history blocks dependent reuse.
  Record old/current basis and targeted applicability assessment on material drift.
- For a result relied on: actual executor/context and, when delegated, configured
  role and actual agent invocation/context ID,
  selected owner, permissions, input versions, output address, returned status,
  inspected evidence and actual effects. Mark unavailable provenance as a gap.
- Copy branch/path/base and scope-appropriate preservation observations/limits;
  claim actor and fresh blockers. Ordinary create does not require all-copy hashes.
- Accessible independent review and actual current candidate. For each candidate
  identify baseline commit and complete task snapshot (including additions,
  deletions and modes), checks and independent review applicability. Follow the
  review/publication owners' snapshot contract; a HEAD commit alone is insufficient
  for dirty work. Record exclusions without losing foreign changes.
- Review: local YAML address and explicit round selector. Apply installed
  `ris-proj-op-review-task/references/report-format.md` for full content/history,
  validity versus approval applicability, exact subject/inputs/checks and actual
  invocation/all-author independence. Read findings/dispositions from that one
  authority, not a copied verdict in Beads or implementation chronology. Keep
  authors of all repairs distinct from reviewer; later adverse/invalid/unsupported
  rounds forbid old-approval fallback. Missing local report gives no approval and
  no remote-availability promise. Tracker holds address/round only for review;
  short work/check/publication/completion facts remain distinct.
- Actual Git remote/primary ref/integrated commit, snapshot checks/reassessment,
  push result and independent remote read-back address/revision.
- Separately: criterion/composition verification, applicable write protection scope
  and source of its guarantee, persisted result, actual closure read-back; tracker
  remote/shared-main authority, required S, observed L/fresh R, push attempt and
  remote reachability confirmation. Keep local expected-content evidence separate;
  moving main supplies neither exact sent bytes nor field equivalence. Do not
  record a local lock as protection against remote writers.
- Operation status `ok|blocked|conflict|error`, factual stopping cause separately
  from confirmed partial effects, uncertainty, first remaining operation, exact
  prerequisite/decision for it, and fresh next recommendation without a claim.
  Apply common recoverable-result/channel facts; a nested component returns to
  this caller without a mandatory next-skill assignment. Response-only or local
  evidence without an inspectable available source leaves an explicit discovery
  gap, not an invented ID, report path or remote prerequisite.

An artifact/flag is not authority that a stage is done. Preserve actual receipt
addresses and versions; inspect files/remote reads where available, rather than
trusting narrative. Missing output permission means an unsaved report and a blocked
dependent persistence claim, not a hidden write. This is evidence, not a scheduler.

## Reconciliation observations

For prior/partial effects, own unfinished work or closed pending-publication work,
load `recovery.md` from this resource's directory. It determines applicability and
returns to the existing SKILL route; neither a note nor this checklist authorizes
transitions. For the affected result convey fresh observations and contradictions,
not a latest-stage flag. A compact reconciliation can use:

```text
operation / actual effect and receipt / input and tested snapshot / current facts
reuse: applicable | missing | inapplicable | uncertain (reason and affected scope)
first necessary operation / owner / prerequisites / remaining gate
```

Distinguish local Git integration/commit, sent Git revision and remote confirmation;
criterion verification, persisted result and closure; local tracker history,
required tracker revision and fresh selected-remote reachability evidence.
Preserve confirmed effects even when their former checks lose applicability.
Later unrelated authorized changes do not erase confirmed revision publication,
but are not accepted by its receipt.
Record input/rule/package changes and the owner's evidence-impact assessment,
including why unaffected results can be reused. Missing notes may be reconstructed
from referenced facts with provenance and gaps; never invent old checks, TDD chronology,
review independence or an unavailable executor receipt. Report unavailable write
permission separately from the ability to inspect and return an unsaved handoff.

For nonstandard copy association, non-idempotent setup, remaining processes or
ambiguous partial effects, a compact addressable result must be available in an
already authorized channel before a dependent irreversible action. If it cannot be
saved or recovered, block that action with the exact missing input. Never invent
review independence, candidate identity, past setup completion or a new mandatory
file/registry to replace missing proof.
