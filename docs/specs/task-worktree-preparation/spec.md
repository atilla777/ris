# Подготовка рабочей копии задачи

Постоянный slug: `task-worktree-preparation`. Родительский эпик: `ris-p20`.
Требования v1 приняты пользователем 13 октября 2026 года. Дизайн принимается отдельно;
этот документ не разрешает реализацию. Подготовка и публикация документов и связанных
записей Beads разрешены отдельно в текущем диалоге.

## Требования

**Цель:** для одной подтверждённой задачи подготовить или проверить Git worktree и передать достаточно сведений для технического планирования в этой копии. Родитель — `ris-p20`.

### Предлагаемые требования и критерии приёмки

| ID | Проверяемое поведение |
|---|---|
| **AC-001** | Скил подтверждает проект, точный ID задачи, исполнителя и разрешённые действия. Не выбирает задачу из очереди и не выводит ID из заголовка. |
| **AC-002** | Перед созданием worktree или изменением окружения проверяет состояние и блокировки задачи. При явном разрешении захватывает свободную открытую задачу либо подтверждает свой захват. Чужой захват не перезаписывает. |
| **AC-003** | Поддерживает обычный Git и явно выбранный Worktrunk. Проверяет доступность и необходимые возможности выбранного инструмента. Если он недоступен или несовместим, сообщает препятствие без молчаливой смены инструмента. |
| **AC-004** | Новую ветку по умолчанию создаёт от актуальной основной ветки выбранного remote после обновления сведений о ней; фиксирует точный commit. Явная исходная ревизия имеет приоритет. Ошибка обновления не подменяется использованием старой копии. |
| **AC-005** | По умолчанию связывает задачу с веткой `task/<ID>` и каталогом `workspace.worktrees/<ID>`. Допускает явные значения и правила проекта. Небезопасное или неоднозначное имя требует уточнения; произвольное преобразование ID не применяется. |
| **AC-006** | Повторный вызов находит и проверяет существующую копию той же задачи. Сохраняет её путь, ветку, HEAD, индекс и незакоммиченные изменения. Не выполняет автоматические reset, rebase, stash или commit. |
| **AC-007** | Занятый чужими данными путь, неоднозначная принадлежность, повреждённая регистрация или незавершённая Git-операция дают явный конфликт либо препятствие. Скил не удаляет, не переносит и не исправляет такие состояния автоматически. |
| **AC-008** | Подготовка окружения — опциональный, явно разрешённый этап с определённым составом действий. Hooks и фоновые действия не считаются завершёнными только по успешному созданию worktree. Готовность копии и окружения сообщается отдельно. |
| **AC-009** | Копирование локальных файлов ограничивается разрешённым составом. Общая база трекера и общие рабочие заметки не превращаются в независимые копии состояния. Worktree не объявляется изоляцией общих ресурсов. |
| **AC-010** | После подготовки проверяет фактические путь, ветку, HEAD и связь с репозиторием; заново разрешает проектный контекст. Передаёт ID, исполнителя, корни текущей и основной копий, состояние изменений, исходную ревизию для новой копии, результат подготовки окружения и ограничения. |
| **AC-011** | При частичном результате сообщает подтверждённые эффекты — например, полученный захват и созданную копию — и конкретный способ продолжения. Не откатывает их молча и не повторяет создание без сверки состояния. |
| **AC-012** | Из `ris-plan-task` и `ris-implement-task` убирается самостоятельное создание worktree. Они получают и проверяют текущую копию без зависимости на новый скил. Прямое планирование остаётся возможным без обязательного worktree и захвата; реализация сохраняет проверки владения перед изменениями. |

**Проверки поставки:** реальные операции через Git и установленный Worktrunk, создание и повторное использование, сохранность изменений, конфликтующие пути и захваты, частичный сбой подготовки окружения, а также второй RIS-проект с другими путями.

**Вне фичи:** технический план, реализация, ревью изменения задачи, публикация, закрытие задачи/эпика, удаление worktree и отдельная команда. TDD и будущий сквозной сценарий остаются отдельными работами.

Имена новых скилов, целесообразность отдельных инструментальных адаптеров и способ передачи результата определим в независимо принимаемом дизайне.
