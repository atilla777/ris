# Решения по ускоренному выполнению простой задачи

## Требования v1

- `decision: accepted`.
- Принявшая сторона: пользователь текущего интервью о фиче эпика `ris-1wa`.
- Принятое содержание: `docs/specs/fast-task-execution/spec.md`, весь файл
  (`section: null`), требования v1; `revision: containing-commit`.
- Основание: после последовательного выбора решений пользователь ответил
  «да» на вопрос об утверждении собранного объёма требований. Затем на вопрос
  о сохранении спецификации и создании связанной записи фичи ответил «дда».
  Это отдельное разрешение на сохранение, независимое ревью и публикацию
  документов Git, создание записи под `ris-1wa` и отдельную публикацию Beads.
- Сводка принятия: понятный запрос до проверенного direct push; без обязательных
  требований/дизайна/декомпозиции/плана как отдельных этапов; без Beads и файлов
  отчётности по умолчанию; текущая подходящая копия; основной агент выполняет
  работу, отдельный субагент проводит независимое ревью; проверки соразмерны,
  TDD условен; существенные решения согласуются адресно; обязательные правила
  проекта сохраняются. Приняты необходимые доработки владельцев операций,
  команда/документация/установка и адресное согласование правил самого RIS.
- AC спецификации — проверяемая запись принятого содержания, а не свидетельство
  реализации. Точные имена и интерфейсы ещё не являются принятым дизайном.
- После публикации `containing-commit` разрешается в полный Git SHA коммита
  этой записи и спецификации; ссылка Beads закрепляет именно эту версию.
- Дизайн и verification отсутствуют. Это решение не разрешает декомпозицию,
  реализацию, захват задачи или закрытие фичи/эпика. Они остаются отдельной работой.

- Принятое содержание: `docs/specs/fast-task-execution/design.md`, весь файл

- Основание: пользователь выбрал вариант «1» для собственной ветки в текущей

  ответил «да». Это отдельное принятие дизайна, а не повторное принятие требований.
- Разрешены сохранение D1 и этого решения, независимое ревью, публикация документов
  Git и согласование design-ссылки в `ris-1wa.1` с отдельной публикацией Beads/Dolt.
- Требования v1 и их решение остаются закреплены на первоначальном опубликованном
  `e4829930e857263659f1f5c36abc70d5dc01e778`: [исходное решение](https://github.com/atilla777/ris/blob/e4829930e857263659f1f5c36abc70d5dc01e778/docs/specs/fast-task-execution/acceptance.md#требования-v1).
  Историческое `containing-commit` в разделе выше относится именно к этому SHA,
  а не к коммиту добавления D1. Содержание `spec.md` не изменяется.
- Совместимость проверена на опубликованной базе
  `8a40f811379180598e36e631cf704cad1aa6a6ce`: изменение после требований касается
  загрузки общих инструкций, context и ресурсов адаптера, не меняет требования
  fast, контракты реализации/ревью/публикатора или выбранный маршрут D1.
- D1 описывает будущие изменения существующих контрактов и правил RIS; они не
  считаются внедрёнными от принятия или публикации документа. Verification
  реализации не записывается. Декомпозиция, реализация, claim и закрытие фичи
  или эпика этим решением не запускаются.
