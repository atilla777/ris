# Решения по подготовке установки RIS

## Требования v1

- **Решение:** `accepted`.
- **Принявший:** пользователь текущего диалога OpenCode, инициатор фичи.
- **Дата:** 15 октября 2026 года.
- **Содержание:** `docs/specs/package-installation/spec.md`.
- **Область:** `section: null` — весь файл требований v1.
- **Ревизия содержания:** `containing-commit` — совместная первая публикация
  неизменённых требований и этого решения. Полный commit ID в ссылках Beads
  устанавливается по фактическому опубликованному Git-коммиту.

Основание принятия — последовательные решения пользователя в интервью:

1. Разделить установку инструментов и полную инициализацию проекта.
2. Полностью заменять установленные скилы и команды вместе с локальными правками.
3. По умолчанию брать актуальную основную ветку GitHub.
4. Первой поставкой сделать установку, обновление и удаление; инициализацию отложить.
5. Перезаписывать совпадающие имена без дополнительного согласования.
6. Поддержать Linux и macOS shell-установщиком.
7. Сохранять прежний пакет временно, автоматически восстанавливать при ошибке,
   а после прерывания сначала восстанавливать при следующем запуске.
8. После обсуждения режимов хранения упростить решение: включать файлы OpenCode
   в проект; прежний локальный режим и исключения Git отменены.
9. Дополнительно разрешить явный тег или Git-коммит.
10. Зарезервировать всё пространство `ris-*` в проектных каталогах скилов
    и команд за пакетом, включая прежнюю ручную установку.
11. Ответом «Да» подтвердить интерфейс из одного установщика, скила
    `ris-manage-installation` и команды `/ris-manage`.
12. После итоговой сводки требований и эскиза поручить «продолжай» — сохранить
    спецификацию и подготовить дальнейшую работу в Beads.

Этот документ сохраняет действительные решения из доступного текущего диалога;
он не утверждает наличие опубликованного экспорта сессии. Для получателя без
чата содержание решений приведено выше. Материальные изменения требований
требуют нового решения, а не перепривязки этого решения к изменённому файлу.

Исходное состояние репозитория при подготовке:

## Декомпозиция и разрешение публикации

Новое поручение пользователя: «Продолжай - доведи до декомпозийии (потом публикуй)».
Оно разрешает завершить подготовку дизайна/декомпозиции, оформить очередь Beads
и затем опубликовать документы в Git и историю этой инициативы в Dolt.
[delivery-plan.md](delivery-plan.md) сохраняет два проверяемых результата W1/W2
с покрытием AC-001–015; W2 блокируется W1. Публикация следует после подготовки
декомпозиции. Реализация W1/W2 этим поручением не запускается.

## Граница трекера и публикации

`ris-0pr` — самостоятельная подготовительная задача. Контейнер реализации
создаётся отдельно как обычный task без искусственного SDLC-эпика и без
заявки на `ris.feature-record/1`. Это не обход доказательств принятия:
задачи получают реальные опубликованные версии требований, дизайна и решений.
Git-публикация и отдельная Dolt-публикация требуют фактической проверки;
локальное сохранение или наличие этого решения не подменяет ни одну из них.
