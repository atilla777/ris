# package-installation — адресная поправка N1 к именам

**Статус:** требования и дизайн поправки приняты пользователем
15 октября 2026 года. Основание — ответ «да (задача установщика будет продолжена
после этого)» на отдельный вопрос о принятии конкретной поправки к требованиям
и дизайну установщика. Решения:
[требования N1](acceptance.md#требования-n1),
[дизайн N1](acceptance.md#дизайн-n1).

Поправка применяется поверх требований v1, дизайна D1 и декомпозиции P1,
опубликованных в Git `51da1068b2124c0cb6de8a87912e0375be7524f4`.
Это отдельный ограниченный delta, а не переиздание прежних полных документов
или изменение алгоритма установщика. База и её решения сохраняются.
Связанная поставка: [единые имена RIS](../skill-command-naming/spec.md),
[принятый дизайн именования D1](../skill-command-naming/design.md).

## Требования N1

В интерфейсе §6 требований v1 и критерии `package-installation#AC-013`:

| Элемент | Вместо | Принято N1 |
|---|---|---|
| Скил управления | `ris-manage-installation` | `ris-port-op-manage-installation` |
| Команда OpenCode | `/ris-manage` | `/ris-port-op-manage-installation` |

Команда точно совпадает с именем скила и использует читаемые маркеры:
пакет RIS, автономное применение без RIS-проекта, одна выбранная операция
install/update/uninstall. Старые имена не сохраняются как алиасы.
Один скил и одна команда по-прежнему используют единственный установщик.
Зависимость от ris.yaml, Beads или предварительной инициализации не добавляется.
Идентификатор и остальные условия AC-013 сохраняются, новых AC не вводится.

Продолжение задач установщика `ris-lr1.1`/`ris-lr1.2` следует **после завершения
унификации имён RIS**. Подготовка требований/дизайна именования сама по себе
не означает завершение унификации. Порядок W1 → W2 и обязательный состав
контейнера `ris-lr1` сохраняются. Это согласование имён и порядка, а не запуск
реализации установщика текущим поручением.

## Дизайн N1

Новые адреса будущих файлов, замещающие соответствующие адреса D1/P1:

```text
skills/ris-port-op-manage-installation/SKILL.md
skills/ris-port-op-manage-installation/scripts/ris-install.sh
commands/opencode/ris-port-op-manage-installation.md
.opencode/skills/ris-port-op-manage-installation/
.opencode/command/ris-port-op-manage-installation.md
```

W1 `ris-lr1.1` размещает прежний CLI по новому script path и использует его
в README bootstrap и в проверках полного fixture-комплекта. Bootstrap raw URL
должен выбирать этот путь в той же выбранной ревизии пакета. W1 по-прежнему
не создаёт production SKILL.md/команду, принадлежащие W2.

W2 `ris-lr1.2` создаёт новый SKILL.md и одноимённую тонкую команду, синхронизирует
установку и проверяет общий комплект с CLI W1. Валидация пакета, self-update,
self-uninstall, README и проверки ожидаемого состава используют новое имя,
не ослабляя требование наличия скила/команды/скрипта управления.

Runtime-флаги CLI, Bash/Git/flock, schema version/journal, upstream,
зарезервированная область `ris-*`, self-copy, lock, snapshot, rollback,
поведение при ошибках и Linux/macOS-проверки не меняются. Новый script или
дублирующий механизм установки этой поправкой не создаётся.

Входы задач читаются как опубликованные v1/D1/P1 **плюс** N1 с отдельными
решениями. Прежние ссылки на базовый Git не заменяются выдуманной новой
ревизией. Сейчас N1 сохранена локально; полный commit и immutable-адреса
её решений устанавливаются после отдельно разрешённой публикации.

До продолжения исполнитель сверяет завершённый результат унификации имён,
текущий состав source-каталога и фактические опубликованные версии N1.
Будущий management-скил не входит в исходную карту 41 существующего скила;
его добавление после унификации увеличивает состав на один скил и команду.

Привязка графового blocker к задаче реализации унификации требует её
подтверждённого ID при декомпозиции. `ris-bsy` — только подготовка и не
подставляется вместо такого prerequisite. До появления этой связи явное
условие продолжения сохранено в документах и заметках задач; наличие
статуса open или попадание в ready не отменяет его.

## Проверка поправки

- Чтением сравнить scoped delta с v1 §6/AC-013, D1 §1 и P1 W1/W2:
  меняются только публичные имена, их производные адреса и порядок продолжения.
- Сохранить старые опубликованные требования, дизайн и решения; новая версия
  решения не переопределяет прежний `containing-commit`.
- Прочитать добавленные заметки точных `ris-lr1`, `ris-lr1.1`, `ris-lr1.2`:
  новые имена/пути и условие продолжения доступны следующему исполнителю,
  прежние поля и связь W2 → W1 сохранены.
- При реализации применить прежние проверки W1/W2 к новым адресам. Локальная
  поправка и статическое ревью не объявляются реализацией или runtime evidence.
