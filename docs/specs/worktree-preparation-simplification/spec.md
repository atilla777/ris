# Упрощение подготовки рабочей копии задачи — требования V2

## Цель и границы

Сократить обязательные действия, загрузку инструкций и отчётность при обычной подготовке worktree задачи RIS, сохранив защиту чужой работы и безопасное возобновление частичного результата. Сравнение действий и объёма обязательных инструкций до/после не считается измерением времени или токенов.

Затрагиваются `ris-proj-op-prepare-task-worktree`, `ris-port-op-prepare-worktree`, выбранные Git/Worktrunk-адаптеры и их условные ресурсы, только относящиеся к подготовке части context/common/handoff, а также стык `ris-proj-flow-execute-task` с его evidence/recovery. В объём входит отмена обязательного `execution.md` как дублирующего журнала этапов полного сценария; соответствующие инструкции и правила должны быть согласованы. Не повторять уже завершённую общую оптимизацию handoff/context из `ris-9wk`.

Не менять политику Beads-статусов и claim, публикацию Git/Dolt, требования к плану, реализации и независимому ревью, приёмку фичи. Новая CLI, обязательный реестр, аналогичный обязательный журнал или автоматическая миграция старых заметок не требуются. Реализация данной задачи требует отдельного поручения.

## Поведение

1. **Обычное создание.** Для подтверждённой готовой задачи со свободными путём и веткой, без запрошенного setup и существенных hooks проверяются точный ID, актор, claim, блокировки, репозиторий, выбранный primary, путь и ветка, применимые побочные эффекты, закреплённая базовая ревизия, фактически созданная копия и доступ к тому же Beads-проекту. Claim подтверждается до мутации, изменяемые условия повторно проверяются непосредственно перед зависимым действием. Следующему этапу передаются адрес и краткий проверенный итог; редкие ветки не исполняются только потому, что описаны в контракте.
2. **Соразмерные проверки.** При обычном создании без hooks/setup не требуется полный обход или хеширование всех tracked/untracked/ignored файлов основной копии и несвязанных worktree. Проверяются путь, ветка, HEAD, регистрация и состояние результата. При reuse сохраняются HEAD, индекс и изменённые файлы, подтверждается связь копии с задачей; при hooks/setup проверяются затрагиваемые ими ресурсы и выходы. Неизвестный эффект запускает адресную диагностику. Проверки не должны обещать неподтверждённую байтовую сохранность; конфликт, сбой или незавершённая операция не устраняются сбросом или удалением.
3. **Контекст.** После создания сверяются необходимые для конкретной операции и получателя настройки: проект и идентичность общего трекера, применимые правила, primary и используемые shared paths. Различие неиспользуемой настройки между основной и рабочей копией само по себе не блокирует передачу; значимое расхождение блокирует только зависимую часть с точной причиной. Запрещены подстановка конфигурации и создание второй базы Beads.
4. **Без обязательных журналов.** Прямой вызов подготовки и полный сценарий не создают и не требуют `worktree.md`, `execution.md` или равноценного обязательного журнала в файле либо Beads по умолчанию. Применимые локальный `plan.md`, заметки о ходе и итоге работы, отчёт независимого ревью и достаточный итог в Beads сохраняются согласно правилам проекта; их не превращают в замаскированный журнал всех этапов. Каждый переход сверяет живые Git/Beads-факты, опубликованные версии и адресные результаты; получателю передаётся только нужный проверенный контекст. Старые отчёты допускаются как подсказка, но не как обязательный или авторитетный источник. Если независимость ревью, применимость проверки или другая необходимая предпосылка перехода не доказуема из доступного результата, зависимый шаг блокируется с указанием недостающего входа.
5. **Восстановление.** При запуске из task-копии `primary_root` берётся из явного ввода либо уже доступного проверенного указания со связью project/repository/current-copy; имя ветки, путь и общий Git dir только подтверждают, но не выбирают primary сами по себе. В no-ID полном сценарии claim или assignee сами по себе не доказывают принадлежность незавершённой работы. Если точный ID/association установить нельзя, зависимое возобновление блокируется, чужая задача не выбирается. Для нестандартной связи задачи с копией, неидемпотентного setup, оставшегося процесса или неоднозначного частичного эффекта до зависимого необратимого действия оставляют компактный адресуемый результат в уже разрешённом канале либо честно блокируются. Выполненные эффекты сверяются перед повтором; сохранённые claim и копия не сбрасываются. При обрыве до передачи результата неизвестное состояние не угадывается.
6. **Инструменты.** Git остаётся вариантом по умолчанию, Worktrunk выбирается только явно или однозначным правилом проекта. Оба пути возвращают сопоставимые понятные результаты с раздельной готовностью копии и окружения. Нет автоматического fallback между CLI и ручного окна для обычного создания. Если запрошена более сильная гарантия конкурентной уникальности, её действительная доступность проверяется отдельно; claim/worktree не объявляются общим CAS.

## Критерии приёмки

- **AC-001.** Новое создание с точным ID и подтверждённой primary/association не требует создания или чтения `worktree.md`, `execution.md` либо их аналога; результат проверен по Git/Beads и передан компактно. Повтор с проверенной association сохраняет существующую копию; при нехватке необходимых сведений возвращает адресный blocker. Отсутствие прежнего журнала само по себе не блокирует.
- **AC-002.** Для обычного пути показаны обязательные чтения инструкций и действия до/после с конкретными условиями загрузки редких веток; не заявлено измеренное ускорение без измерений.
- **AC-003.** Обычное создание без hooks/setup не обходит и не хеширует все файлы основной копии; регистрация, ветка, HEAD и затрагиваемая область проверены, сохранность описана только в пределах наблюдений.
- **AC-004.** Reuse с dirty-файлами, коллизия, неудача, частичное создание и нестандартный setup не затирают работу: при доказанной принадлежности и эффектах повтор исполняет лишь остаток, при неопределённости блокирует. В полном потоке без `execution.md` доступны обязательные план, локальный ход/итог, отчёт ревью и tracker-итог; непроверяемая предпосылка останавливает зависимый переход.
- **AC-005.** Различие неиспользуемого `sources.product` не блокирует подготовку; смена идентичности трекера или используемого shared path блокирует соответствующую передачу без тихой замены настроек.
- **AC-006.** Сохранены проверки прав, claim, блокировок и primary; Git по умолчанию и явно выбранный Worktrunk без fallback; результат отдельно различает `copy: ready` и `environment: not-requested|ready|error`.
- **AC-007.** Согласованы исходные и установленные контракты подготовки, full-flow/evidence/recovery, относящиеся правила и документация. Чтение, адресные статические проверки и независимое ревью не оставляют замечаний высокого/среднего уровня; инструкции не проверяются живыми агентными сценариями. Если добавлен исполняемый код, выполняются применимые детерминированные проверки.
