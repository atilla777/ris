# Принятие компактных команд RIS

## Требования v1

- **Решение:** `accepted`.
- **Принявший:** пользователь текущего диалога OpenCode, инициатор изменения.
- **Дата:** 16 октября 2026 года.
- **Содержание:** `docs/specs/compact-commands/spec.md`.
- **Область:** `section: null`, требования v1 целиком.
- **Ревизия содержания:** `containing-commit` при первой совместной публикации
  этой версии требований и решения. До публикации полный Git SHA и immutable
  refs не заявляются; после публикации адрес решения фиксирует containing commit.

Происхождение решения из доступного диалога:

1. Пользователь запросил анализ длинных названий и избыточного набора команд
   с точки зрения поиска через автодополнение.
2. Выбрал компактное меню: «Компактное. А может для отличия proj от автономных
   использовать risp- risb- (base)».
3. Получил предложение полного набора из 18 команд: 14 проектных и четыре
   автономных, с сохранением технических имён скиллов и явным контрактом
   каждого входа; сокращение меню не удаляет скиллы.
4. На вопрос о второй команде автора ответил: «пока одного хватит
   /risb-author-skill (только его и подобные можно сократить как нибудь до
   /risb-skill)».
5. После сводки с `/risb-skill`, выборочным предметным сокращением имён,
   сохранением набора из 18 команд и предложения согласовать итоговую таблицу
   и критерии, сохранить спецификацию и запланировать реализацию ответил «да».
6. На отдельный вопрос «Подтверждены 18 команд с /risb-skill. Разрешаешь также
   сделать коммит и push только новой спецификации и её записи в каталоге,
   а затем создать и опубликовать задачу реализации в Beads? Это позволит
   следующей сессии использовать опубликованные требования; реализацию команд
   не запускаю» выбрал «Да, опубликовать (Recommended)».

Критерии спецификации формализуют согласованный интерфейс и сохранение
действующих контрактов доставки; они не добавляют новые предметные операции.
Документ сохраняет доступное решение, не утверждая наличие опубликованного
экспорта сессии. Технический дизайн отдельно не принимался. Разрешены публикация
этих требований/решения и записи каталога, создание и отдельная публикация
плановой задачи Beads. Начало реализации миграции не разрешено этим поручением.
