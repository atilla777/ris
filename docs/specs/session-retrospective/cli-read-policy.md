# Поправка: штатное CLI-чтение без предварительного fitness witness

## Принятие и область

15 октября 2026 года пользователь после обсуждения чрезмерного CLI-барьера
поручил: «Исправь скиил потом публикуй изменения». Этим принята ограниченная
замена runtime-политики получения истории; задача реализации — `ris-48d`.
Поправка имеет приоритет над предварительным initialized/scoped-fitness gate
в `spec.md` §8/AC-013 и `design.md` §§3, 9, 11. Остальные требования,
разделение portable base / RIS wrapper и исторические решения сохраняются.
Закрытые feature-record refs и прежние свидетельства не перепривязываются.

## Принятое поведение и техническая граница

- Запрос ретроспективы разрешает owned reader выполнить фиксированные
  `opencode --pure --version`, `opencode --pure session list --format json
  --max-count 5` и `opencode --pure export <точный ID>` в выбранном проекте,
  если пользователь или правила проекта явно не ограничили CLI.
- Отдельные доказательства инициализации БД/схемы, инвентаризация служебных
  путей и runtime fitness witness не требуются. Их отсутствие само по себе
  не основание запрашивать экспорт вместо штатного чтения.
- Уже предоставленный экспорт предпочтителен. Без ID/экспорта показывается
  список и задаётся вопрос выбора; последняя сессия молча не выбирается.
- `--allow-cli` остаётся явным разрешением фиксированных вызовов reader,
  но больше не означает проверку инициализации/fitness. Version gate reader
  (1.18.33), shell=False, ограничение argv, JSON/identity/cutoff и редактирование
  чувствительных данных сохраняются. Ошибка получения дочерней сессии через
  CLI запрещает дальнейшие CLI acquisitions внутри того же вызова reader;
  уже доступная история остаётся полезным partial-результатом с явными gaps.
- Обычные метаданные, DB/WAL housekeeping и собственные логи OpenCode вне
  разрабатываемого проекта допустимы. История и её смысловые связи, файлы/Git
  проекта, задачи и телеметрия защищены. Известный выход за эту границу,
  в том числе служебный путь внутри проекта, блокирует CLI.
- При конкретном признаке bootstrap/migration, запросе настройки, ошибке CLI/
  reader, неподдерживаемой версии или несовпадении проекта сбор через CLI
  прекращается. Не подтверждать prompts, не чинить/инициализировать хранилище,
  не обходить ошибку повторами. Предложить готовый экспорт либо уже доступный
  разрешённый GET. Обобщённой ошибки reader достаточно для остановки;
  раскрывать raw stderr и исследовать внутреннюю БД не требуется.
- Это практическое разрешение штатного клиента, не техническая гарантия
  отсутствия скрытой автоматической миграции. Reader не становится детектором
  всех таких эффектов. Для требования строгого отсутствия записей нужен
  предоставленный источник или уже разрешённый read-only интерфейс.

## Проверка поправки

Проверки — чтение before/after сценариев, source/install parity, reader help
и независимое статическое ревью. Не запускать поведение агентов для проверки
инструкций. Старый scoped oracle сохраняется как историческое свидетельство,
а не условие каждого запуска. Поправка не доказывает live CLI-безопасность,
не повторяет приёмку всей фичи и не разрешает аналитику исполнять transcript,
SQL, тесты, исправления либо сохранять отчёт без отдельного запроса.
