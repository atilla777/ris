# Решения по сквозной связности RIS

## Требования v1

- Решение: **accepted** для требований обсуждения, отражённых в [spec.md](spec.md).
- Принявший: пользователь текущего диалога OpenCode, инициатор аудита/изменения.
- Дата: 15 октября 2026 года.
- Path: `docs/specs/sdlc-continuity/spec.md`; section: null, требования v1 целиком.
- Content revision: `containing-commit` при первой совместной публикации
  неизменённого содержания и этого решения. До публикации immutable refs pending.
  Ссылка будущей задачи должна закрепить фактический полный SHA, а не литерал.

Это фиксация действительных решений доступного разговора, не утверждение
наличия опубликованного экспорта сессии и не новое принятие от имени пользователя.
AC-001–016 — проверяемые следствия согласованного поведения; технические предложения
остаются в отдельно предложенном D1.

### Основания и порядок уточнений

| Решение | Ответ пользователя и смысл |
|---|---|
| R1 — результат/навигация | На сравнение обязательного next prompt с отдельной навигацией выбрано «1»: атомарные операции обеспечивают восстанавливаемый результат; сценарии/внешний workflow управляют переходами; ручная навигация read-only отдельно |
| R2 — короткий вход | Пользователь добавил идеал `/<команда> <номер bead>` для большинства атомарных проектных стадий; конфигурация/defaults и источники восстанавливаются исполнителем |
| R3 — standalone | На вопрос о самостоятельных задачах/контейнерах выбрано «1»: без искусственного эпика/feature-record |
| R4 — parent | Пользователь потребовал отдельного завершения родителя человеком/оркестратором/сценарием; затем выбрал «1»: содержательная самостоятельность ребёнка, структурный parent допустим, связанные источники читать можно |
| R5 — публикация планирования | После сравнения локального и законченного результата пользователь описал ручные эпики/фичи с публикацией и один Git push в конце leaf-разработки; ответил «да» на default публикацию законченных планировочных операций при явно ограничиваемом локальном вкладе |
| R6 — технический владелец | Пользователь уточнил: публикация лишь вызывается планировщиками, исполняется отдельным общим владельцем; согласованная сводка сохранила отдельных Git/tracker owners и обязанность проверить совокупный результат |
| R7 — сохранение подготовки | На конкретное предложение сохранить требования/решения, создать подготовительную задачу, подготовить отдельно принимаемый дизайн и опубликовать Git/Dolt ответ: «да и сразу покажи промт для продолженяи работы в новой сессии» |

Первоначальное предложение обязательного следующего скила в атомарном отчёте
пересмотрено R1, не сохраняется параллельным требованием. Первоначальный выбор
«публикация всегда отдельно от планировщика» уточнён R5/R6: законченный владелец
планирования вызывает публикацию, её алгоритм не присваивает.

## Дизайн D1

**proposed, не принят.** [design.md](design.md) разрешено подготовить, проверить
и опубликовать как кандидата. R7 не принимает его конкретные технические решения.
Отдельный ответ на предъявленный D1 ещё необходим. Нет выдуманного design
acceptance, feature-record реализации или подтверждённого implementation ID.

## Разрешённый объём подготовки

Подготовительная standalone task — `ris-bxc`, key
`ris:sdlc-continuity:preparation:v1`. Документы требований/решений/аудита/D1,
ссылка в индексе, статические проверки, независимое read-only review,
Git commit/push и отдельная проверенная публикация Dolt разрешены.
После полного проверенного результата и Git-публикации разрешено отдельно
закрыть только подготовку по правилам проекта. D1 при этом может оставаться
proposed: критерием подготовки является кандидат, а не его принятие.

Реализация изменений пакета и миграция имён не разрешены этим решением.
Параллельная `ris-1fq` имеет собственного исполнителя; её запись и связи не
изменяются подготовкой. Полная исходящая Dolt history проверяется отдельно;
новая неподтверждённая чужая инициатива не получает разрешения из R7.

## Вход новой сессии

Источники — запись `ris-bxc`, опубликованные документы этого каталога и актуальные
контракты установленного пакета. Локальные `.sdlc/tasks/ris-bxc/` дополнительные.
До завершения подготовки: «Продолжи подготовку сквозной связности RIS по ris-bxc».
После её завершения следующий результат: «Обсуди и согласуй дизайн сквозной
связности RIS по опубликованным материалам ris-bxc».
Последний вызов не переоткрывает подготовку и не запускает реализацию; D1 нужно
прочитать и предъявить, не объявлять заранее принятым. Специальная slash-команда
навигации пока не установлена и здесь не выдумывается.
