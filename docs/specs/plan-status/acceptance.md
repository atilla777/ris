# Принятие требований компактного обзора плана

## Требования v1

- Решение: `accepted`.
- Принял: пользователь текущего диалога OpenCode, 17 октября 2026 года.
- Содержание: `docs/specs/plan-status/spec.md`, версия v1, `section: null`.
- Ревизия содержания при совместной публикации: `containing-commit`.
  До публикации это локальная принятая версия; неизменяемая Git-ссылка ожидается.

Основание — запрос показать незакрытый план Beads компактно, с иерархией,
блокировками, основными атрибутами, рекомендацией и slash-командой. После
предварительного согласия пользователь отдельно попросил интервью.

В шести последовательных вопросах пользователь ответил «1», подтвердив:

1. Сначала продолжать начатое; иначе выбирать по приоритетам и зависимостям.
2. Показывать всё незакрытое дерево, по короткой строке, без скрытых записей.
3. Основные атрибуты, дополнения по наличию, прогресс контейнеров и сведения
   о требованиях/дизайне фич.
4. Добавлять понятный этап только при достаточном основании, иначе обозначать
   неизвестность или неподтверждённость.
5. Включать все незакрытые рабочие записи, в том числе баги и standalone.
6. Делать лёгкий обзор по Beads и подробно проверять основание рекомендации.

Затем пользователю был предъявлен итог со скилом `ris-proj-op-show-plan`, командой
`/risp-status`, формой без аргументов и с ID, составом обзора, границами read-only,
применением существующего навигатора и методом проверки. На точный вопрос
«Сохраняем эти требования в спецификацию и оформляем задачу в Beads?»
пользователь ответил «да».

Сохранённый spec.md разворачивает этот итог в критерии AC-001–AC-012 без
добавления новых пользовательских возможностей. Это принятие требований и
разрешение оформить самостоятельную задачу, не принятие будущего технического
дизайна, не начало реализации, не установка и не закрытие задачи.
