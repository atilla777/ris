## Среда и фактический охват

12 октября 2026 года, Linux, OpenCode **1.18.33**, `openai/gpt-6.1-sol`. Исходная ревизия `b83bd0144aab2beab96df45989a9ed07822df7b0`; проверяются исходники/установка этого согласованного изменения. SHA-256 отсортированного JSON manifest всех файлов 34 source-скилов: `e640645e9b64e4c8d710d0f650f8104f9e27cb4633453c9470db9c097e1d2555`. После runtime-запусков manifest проверен повторно; source и installation совпадают byte-for-byte, включая ресурсы.

Реальные `opencode run --pure --format json` выполнялись в отдельных Git-инициализированных fixture-проектах вне RIS-репозитория. В autonomous fixture установлен **только** `ris-okf-base` с ресурсами; RIS config/tracker/других RIS-скилов нет. В проектных fixture установлены common/context/base/wrapper, у потребителей — также их реальные content methods. Внешние skill scans отключены; bash/task/network запрещены, кроме ограниченных filesystem inspection commands в проверках realpath. Skill loader и read/edit tool events сохранены; файл «успешно» сам по себе не считается oracle.

Project A: `docs/rules/`, `docs/product/`, дополнительный разрешённый `extra/knowledge/`; правила требуют английского языка. Project B: `knowledge/policies/`, `knowledge/world/`, `extra/knowledge/`; правила требуют русского языка. Config v2 содержит только нужные `sources`; нет workspace/adapter/execution/specs. Обычный `plain.md`, соседние области и установленные ресурсы сохраняются. Авторские product-источники самого RIS не правились.

49 CLI-вызовов включают последовательные операции, продолжения после отдельного fixture-owner принятия и четыре диагностических запуска (см. ниже). Сохранялись prompt, package identity, session, tool events, baseline/after SHA-256 и фактические дельты. Fixture-приёмка проверяет механизм, не представляет живое принятие правил владельцами иных проектов. Локальные полные traces и runner находятся в `.sdlc/tasks/ris-p20.2/`; опубликованная таблица ниже содержит достаточные наблюдения и ограничения без зависимости от этих локальных файлов.

## Диагностика и границы evidence

- Первый Project B create остановился из-за противоречия английского fixture-content русскому правилу; следующий edit корректно сообщил missing input. После явного разрешения перевода fresh Project B прошёл все операции, rules/config не ослаблялись.
- Первый external-root запуск с запрещёнными path-inspection tools остановил запись: actual realpath не был доказан. После разрешения **только** path inspection новая fixture успешно создала разрешённый внешний бандл. Это ограничение среды, не основание обходить scope checks.
- Первоначальный symlink запуск также остановился при недоступной инспекции; дополнительные root/nested symlink runs с реальным `realpath`/`stat` установили запрещённые внешние targets и неизменность bytes.
- Text skills не предоставляют filesystem CAS/транзакцию. Stale и partial cases показывают обнаружение/остановку в проверенных условиях, не гарантию против всех races. Claim/lease не используется как защита content updates.
- Проверка формата — чтение pinned specification и реальных файлов; отдельные Python YAML/hash/index/log oracle проверяют effects. Новый публичный validator/CLI/MCP, network dependency, новый OKF config field и автоматическая миграция не вводились.
- README, AGENTS, фактическая architecture map, нормативный каталог/profile и текущие pointers соответствуют новой согласованной поставке. Прежние accepted спецификации сохраняют свои решения с явным переходным примечанием; ordinary feature Markdown не стал OKF. Эти синхронизированные claims публикуются только вместе с проверенными source/install.
- Один набор наблюдений подтверждает эту поставку в OpenCode 1.18.33; универсальная стабильность модели и совместимость иных клиентов не заявляются. Неизвестные author-owned product baselines не требуются миграцией, их currency не подтверждалась.
