# Проверки упрощения подготовки фичи (`ris-bf4`)

Дата: 2026-10-13. Основание: [AC-001–AC-007](feature-preparation-simplification.md).
Это отчёт проверок изменения, не новая спецификация, реестр или принятие
реального продукта. Исходники и установленные копии изменены согласованно;
состояние публикации самой задачи RIS проверяется отдельно.

## Что изменено

- Подготовка заканчивается опубликованными requirements/design, отдельными
  решениями и удалённо проверенным ID. Декомпозиция начинается отдельно по ID.
- Каждый самостоятельный неинтерактивный результат сценария выполняется в
  субагенте; ведущий ведёт разговор/принятие и получает адреса/краткие результаты.
- Единый пересмотренный `ris.feature-record/1`: опубликованный полный Git commit,
  путь, смысловой раздел и immutable адрес отдельного решения вместо обязательных
  scoped digests. `containing-commit` в решении разрешается по его pinned адресу;
  трекер содержит полный commit. История принадлежит Git, не полю `history` Beads.
- Обычное создание best-effort с all-state key/slug/spec сверкой; существующие
  обновления сохраняют требование реальной защиты. `/2`, dual API и миграции нет.
- CLI-first ветка публикации адаптера проверяет всю исходящую историю по каждому
  commit/parent, включая промежуточные изменения, и независимый remote snapshot.

## Реально исполненный изолированный проход

Среда: OpenCode tools, `bd 1.3.1`, native Dolt `2.4.1`, Git; scratch-проект
`/tmp/opencode/ris-bf4-live/project`, отдельные bare Git remote и file Dolt storage.
Не использовался рабочий трекер RIS для создания тестовой фичи.

Ответы и отдельные принятия — **synthetic fixture authority**, не живое принятие
человеком требований реального продукта. Ведущий последовательно передавал
известные ответы, читал полное конкретное содержание до отдельных решений и
обсуждал sync/async после требований. Каждый перечисленный дочерний результат
получен настоящим вызовом `general` через инструмент Task:

1. Изолированная setup/preflight операция установила epic `project-436`,
   раздельные remotes и проверенный исходный snapshot.
2. Селектор рекомендовал выбранный небольшой исход: экспорт выбранных заметок.
3. Формулирование v1 и v2 вернуло реальные пробелы вместо догадок; ведущий
   предоставил дополнительные fixture-ответы. v3 сохранило устойчивые AC.
4. Прямой document-only save сохранил точные requirements и отдельное решение
   без feature ID. Design-base сравнил sync/async, получил технический выбор
   и вернул partial-output предложение владельцу требований, не изменяя поведение.
5. Другой document-only save сохранил отдельно принятый дизайн, оставив требования
   и прежнее решение неизменными.
6. Независимый reviewer проверил конкретные входы. Отдельная counterfactual копия
   с возвратом partial output получила высокое CF-001; repair-вызов восстановил
   принятые байты, свежее независимое ревью прошло до публикации. Повторного
   принятия неизменённого содержания не потребовалось.
7. Git push трёх документов и независимый clone подтвердили commit
   `36f340e8ddd319897ed6728ce5dedc5f5dd1b846`. Оба решения с
   `containing-commit` сопоставлены с конкретным содержанием этого commit.
8. Адаптер проверенно создал `project-436.1` под epic, без детей, с обоими
   опубликованными refs. Контролируемо отброшенный ответ create восстановлен
   all-state сверкой: **один create, ноль recovery mutations**, тот же ID.
9. Отдельный Dolt push отправил полный разрешённый issue/membership/counter
   состав. Независимый clone подтвердил snapshot
   `sr8o2cut7r7rk538kcnq1mcp4mccr5rm`, точные refs, parent, пустые дети/блокеры.
10. Новая независимая декомпозиция получила только project/config/ID; не читала
    chat, кандидаты, answer bank или локальные заметки. Прочитала опубликованные
    документы/решения и проверила одну достаточную задачу: дети `[]`, изменений `[]`.

Git и Dolt partial-readback injections после настоящего push отдельно возвращали
`blocked`; восстановление выполнило независимое чтение известного snapshot,
**без второго push, нового ID или повторного принятия**. Это контролируемые
отказы чтения, не доказательство настоящего сетевого outage.

## Отказные и revision-проверки

### Дополнительный живой проход AC-002

После независимого ревью, которое обоснованно не засчитало synthetic authority
как человека, ведущий провёл фактический question-tool диалог с пользователем:

1. Неизвестное поведение при сбое: пользователь выбрал «Ошибка без результата».
2. После показа конкретного поведения/AC-001–AC-005 отдельно выбрал
   «Принимаю требования». Document-only исполнитель сохранил принятую версию.
3. Design-base обнаружил, что отклонение некодируемого UTF-8 меняет поведение,
   и вернул вопрос владельцу требований. Пользователь выбрал отказ без результата,
   затем отдельно «Принимаю уточнение» для точной Validity/AC-004 правки.
4. После сравнения sync/async без worker пользователь выбрал синхронный контракт.
   Полный конкретный дизайн был показан и отдельно принят: «Принимаю дизайн».
5. Независимый reviewer проверил оба принятых content/decision snapshots;
   замечаний нет. Git-публикация и отдельные clones подтвердили первоначальные
   требования `ca214c16041a4844bbf328b8eefa671ec62b7e1f` и amended requirements/
   design `b455cf18156da38db92b92c01fd10adb7ec38b70` в изолированном Git remote.

Это **живое принятие человеком изолированного примера**, не согласование реального
продукта или реализация экспортера. Отдельные решения опубликованы в
`docs/specs/live-export-notes/decisions.md`; первоначальное pinned на первый commit,
amendment и design — на второй. Реальное копирование старого решения во второй
commit проверено как negative case: оно не возобновляет принятие и не разрешает
перепривязать `containing-commit`. Сохраняется адрес оригинального решения.
Эта находка уточнила единый контракт и save-ресурсы; старые tracker-записи не менялись.

Первоначальные требования, правка и дизайн принятого примера остаются отдельными
Git-результатами. Для AC-002 выполнены шесть реальных вопросов/решений и десять
Task-вызовов, включая один resume: executor сначала вернул несохранённый кандидат,
ведущий не пропустил такой handoff и потребовал фактический адрес/read-back.
Требования не перепринимались для design-only либо публикационного recovery.
Независимое ревью ошибочной counterfactual копии и её repair до публикации
описаны в первом проходе; реальный живой кандидат замечаний не получил.

| Проверка | Фактический результат / предел |
| --- | --- |

## Сравнимые наблюдения и ограничения

Сравнение — формы передачи и конкретных error/retry patterns, не времени/цены:

- Прежний source сценария: 266 строк; новый: 158 строк. Исходники компонентов
  ведущий не загружает для маршрутизации; потребители читают результат по адресу.
- В предыдущей наблюдавшейся сессии dependency-field и heading/newline ошибки
  попадали в ведущий диалог. В новом fixture внутренних Beads/Dolt checks у
  ведущего нет; два checker representation errors (LONGTEXT whitespace и omitted
  SQL NULL) остались у адаптера и исправлены до успеха без повторной мутации.
- Три formulation-вызова отразили обнаруженные material/precision gaps; это
  содержательные уточнения, не слепые повторы записи. Первичная публикация:
  один feature create, один Git push и один Dolt push после baseline setup;
  controlled recovery не добавило мутаций.
- Возвращались краткие адресные handoff, не полные методики/дампы. Полный объём
  прочитанных владельцами данных остаётся в отчётах; число строк файла не равно
  runtime tokens. Токены, стоимость, активное время и сопоставимый baseline не
  измерены; ускорение или удешевление не заявляются.
- В изолированном live-проходе от setup до последнего design-only update refusal
  было 19 фактических bounded Task-вызовов (включая отдельные revision/negative
  проверки). Это число тестовых операций, не оценка числа агентов обычной сессии.
  Сравнимый полный объём handoff в байтах старого прохода недоступен; его снижение
  не заявляется по коротким ответам нового прохода.

Независимое ревью самой поставки и итоговая структурная/OKF проверка фиксируются
для конкретного конечного дерева в локальном отчёте задачи. Публикация RIS Git,
защищённое завершение `ris-bf4` и её Dolt-публикация — отдельные эффекты; этот
fixture-отчёт сам по себе не утверждает их успех.
