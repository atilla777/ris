- `section`: `null` (весь файл).
- `revision`: `containing-commit` — полный Git-коммит, содержащий это решение
  и принятую спецификацию; до публикации immutable reference остаётся pending.

Пользователь принял предложенные уточнения неоднозначных случаев,
имя `ris-execute-task`, постоянный slug `task-execution`, оба пути документов
и размещение feature task под подтверждённым открытым эпиком `ris-01r`.
Разрешено сохранить требования и решение и создать либо сверить feature task
после проверки опубликованных ссылок. Исходный запрос — использовать
`ris-specify-feature` для формулирования, принятия, сохранения и проверки
feature task по результатам интервью.

Сохранение меняет только оформление статуса принятия, местоимение источника
и оформление проектных ссылок; содержательные требования, порядок операций,
исключения и критерии принятого кандидата сохранены.

Решение относится только к требованиям. Дизайн отсутствует и принимается
отдельно; создание feature task не устанавливает готовность к декомпозиции
или реализации и не разрешает начать реализацию. При создании ссылки
`design` и `verification` имеют значение `null`.

кандидата. Дизайн принимается независимо от требований.

Историческое решение requirements-v1 выше относится к исходному коммиту
`e0e110c13aa6627fdc4e61869c77a570e968df4e`: его `containing-commit` не
перепривязывается к коммиту дизайна. Сохраняется исходный immutable address:
https://github.com/atilla777/ris/blob/e0e110c13aa6627fdc4e61869c77a570e968df4e/docs/specs/task-execution/acceptance.md#решение-requirements-v1
Требования в `spec.md` и весь объект requirements в feature record не меняются.

Это решение разрешает сохранение принятого дизайна и отдельного evidence.
Оно не запускает реализацию, захват, декомпозицию или закрытие фичи/эпика.
Обновление design в feature record требует опубликованных ссылок дизайна
и решения и независимо установленного защищённого окна записи по контракту
адаптера; локальное сохранение не завершает combined-операцию.
