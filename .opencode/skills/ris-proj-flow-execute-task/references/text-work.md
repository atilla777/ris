# Text-only implementation route

Read only when the selected task changes text without executable-code behavior.
The `task-implementation` recipient owns the content result and checks; the leading
scenario keeps transitions/dialogue. Preserve accepted scope and copy/claim guards.

Choose by responsibility, not extension or the presence of RIS in a repository:

| Task subject | Content owner |
|---|---|
| RIS package or RIS-integrating skill source | `ris-proj-op-author-skill`, composing its base and checking integration |
| Autonomous skill source, including in a RIS project | `ris-port-op-author-skill` |
| Authorized documentation synchronization with inspected implementation | `ris-proj-op-update-documentation` |
| Explicitly selected project OKF format operation | `ris-proj-op-manage-okf-bundle` with explicit project/root/operation/write scope; caller retains content ownership |
| Ordinary bounded Markdown edit without another content owner | Direct editing against the accepted task/plan/project rules |

Do not use format editing to approve new normative content or convert ordinary
Markdown into OKF. Do not invoke product/architecture authors to make unaccepted
requirements/design decisions. A blocker returns to the single leading dialogue.

Pass actual current/primary roots, confirmed actor/task, accepted inputs and plan,
allowed files and precise report address. Before any change the recipient freshly
checks task ownership, blockers, current-copy association and foreign changes using
the selected adapter/current-copy contracts. If no owner supplies those guards for
this textual route, the recipient performs the bounded adapter checks itself.
Foreign claims, changed inputs or forbidden scope block the change.

Discover the task's own accepted source versions/decisions and constraints by
exact ID reads and links, and the plan through context-checked primary
`workspace.tasks/<ID>/plan.md` or its inspected override. Structural parent is
context, not a replacement contract or forced feature-record. Missing evidence
names the exact source/path/permission gap. Installed-copy edits require the
host's customization instructions as applicable and explicit synchronization
authority; canonical source and full affected installed resources stay in parity.

Require substantive content/criterion coverage, links/resource accessibility,
preservation of neighboring decisions, source/install parity where authorized,
affected checks and actual full final diff/snapshot. Keep an identified
`implementation.md` (or explicit/project address) with input/check/effect history.
Text work needs no invented failing test. If the change affects code behavior,
including a helper script introduced in a mixed task, return to the mandatory
`ris-proj-op-implement-task-tdd` route; do not avoid TDD by calling it documentation.

Repairs use the same content owner and original task with stable finding IDs,
fresh claim/blocker guards and affected checks. Return the new snapshot and
dispositions for independent review; the implementation author cannot supply
independent approval, publication, acceptance or closure.
