# Finish the actual ancestor chain

Shared execution-flow tail, owned by `ris-proj-flow-execute-task`; full and tracked
simple-task execution apply this resource after their selected task's exact close
and separate tracker publication are confirmed. Bugfix inherits the full route.
This is not a new skill, tracker algorithm or substantive acceptance operation.
Direct status, verification and exact-container close never activate this tail.

## Caller: admit and select the execution mode

A full execution request includes ordinary child-based closure of its task's
eligible ancestors unless the user or applicable project rules prohibit it.
Respect exact scope limits; never expand a verification-only or leaf-only request.
Read the completed task's actual parent relationship through the selected adapter,
not dotted ID prefixes or titles. Confirm no parent means a successful no-op,
without requiring a role or launching an agent. Unknown is not absent.

For Fast (`ris-proj-flow-execute-simple-task`, including suitable natural selection),
the main agent applies the ascent below **inline** through the same container owner
and selected adapter. No `container-completion` role, fresh subagent or transfer of
its own context is required. Load/apply common, context only for needed settings,
the selected adapter and `ris-proj-op-complete-container` before their operations.
Keep the same predicates, authority, separate publication and recovery below.

For full task execution (including bugfix through full), retain mandatory fresh
delegation. For an allowed chain resolve `container-completion` through context's execution-role
resource, check the configured executor's availability and caller/child permissions,
and **actually launch one fresh subagent for the entire chain**. Check a known
needed role before dependent effects; unavailable delegation leaves the task's
own completion/publication intact and the cascade explicitly unfinished. Do not
silently perform the cascade in the saturated lead context or switch models.
`standard` is the initialization recommendation, not a package fallback.

Pass only project/current copy/config, exact completed task ID, confirmed close
and tracker-publication facts, this resource's accessible installed address,
selected adapter, attributable cascade/shared-history authority and user limits.
No implementation history, child review reports or inherited-chat assumption.
The recipient loads/applies common, context, the selected adapter and the existing
`ris-proj-op-complete-container` owner before their operations. Its bounded goal
is the chain result below, not feature verification, repair or next-task execution.
The lead checks actual invocation and returned effects before reporting success.

## Acting owner (Fast lead or full-flow recipient): ascend only real parents

1. Freshly confirm the starting task is exactly the supplied closed ID in the
   selected project. Resolve a unique immediate parent from actual membership.
   At each hop verify the parent link and the preceding child's membership;
   detect repeated IDs/cycles, multiple parents, unsupported types or contradictory
   links and stop with `conflict`/a precise capability gap, never choose a branch.
2. For that exact parent apply complete-container's **ordinary child-based** path:
   complete all-status nonempty direct children, all strictly `closed`, no active
   parent blockers, native non-force exact close and independent read-back. Use
   actual kind/content/relationships, not an absent feature payload as a classifier.
   Do not claim/reassign parents, change edges/content, execute children, audit
   decomposition, inspect descendants' deliveries or repeat specs/tests/Git/review.
   Never substitute substantive verification or administrative close for an empty
   or ineligible child set. The existing owner retains its native predicates and
   separate tracker-publication method; no copied CLI algorithm here.
3. Confirm each newly closed parent's separate tracker publication through that
   owner and the adapter before ascending again. Forward the actual shared-history
   authority; local close or the leaf's earlier publication is not this confirmation.
   Already closed parents are reused, not reclosed: reconcile any known pending
   publication through the adapter first, then continue upward from live links.
4. Stop normally at the root, an explicit authorized boundary, or the first parent
   with nonclosed direct children or active blockers. Report that parent and relevant
   IDs/reasons; no sibling-branch traversal or automatic work selection. A normal
   ineligible stop completes this bounded check, not the parent's work. An empty
   child set inconsistent with the preceding membership, incomplete reads, native
   refusal, changed membership, missing permission or ambiguous effects stops the
   dependent cascade with the cause's `blocked|conflict|error`, not vacuous success.

## Partial effects, recovery and combined report

On timeout/lost response/failed close or push, stop dependent writes. Reconcile
real status, membership and exact required publication revision through the same
owners before retry; no blind inline continuation or relaunch while a previous
writer/recipient may still write. Resume in the applicable caller mode: Fast inline,
full/bug fresh recipient. Never weaken the full route by selecting Fast just for
its tail.
Reuse confirmed closed IDs and reachable revisions; never reopen/reclose, repeat
confirmed pushes, or replace a known required revision with a newer tip to hide debt.
An explicitly continued unfinished execution may finish only this authorized tail
even when its starting task is already closed; a random closed-ID query does not
authorize a new cascade. No new mandatory journal, registry or report file.

Return `ok|blocked|conflict|error`, starting ID, newly closed versus reused parents,
their checked local statuses and separate publication confirmations/revisions,
normal stopping point/reason or precise unfinished operation and preserved effects.
Distinguish skipped-by-user, no-parent and normally ineligible from failed/unverified.
The lead reports leaf Git/close/publication separately from the ancestor result.
Cascade failure never undoes leaf completion, but the combined result cannot be
called fully complete while a required cascade operation/publication is unfinished.
Child-based parent status is not fresh independent acceptance of the whole feature.
