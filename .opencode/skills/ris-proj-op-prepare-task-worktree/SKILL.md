# Prepare one RIS task's working copy

Before feature preparation claim/copy admission, apply installed specify-feature's
owned `references/stage-prerequisites.md` to readable requirements prerequisites
independently of native blocks. For execution, inspect any actual parent confirmed
as a feature and its needed decisions/results/native blockers too. This does not
infer feature kind from membership or weaken claim/native refusal/copy guards;
ordinary and native bug subjects keep their existing scoped contracts.

Own the combined **project copy and environment handoff**. Load/apply installed
`ris-proj-lib-common` with its applicable resources, `ris-proj-op-resolve-context` for this operation's
rules, selected tasks adapter and needed shared paths, and
`ris-port-op-prepare-worktree` for the portable method. Check availability and actual
results, not names. Direct invocation requires no execution role. Only the base
loads the selected worktree adapter; the tasks adapter owns tracker effects.

## Project inputs and preflight

Require selected project, exact task ID, actor, current working copy, purpose
`execution` (default) or explicitly selected `feature-preparation`, and explicit
permissions for claim, copy creation/reuse, environment actions and optional
evidence writes. Never choose a task or infer its ID from a title. Prepare context
for these inputs; read the applicable project rules. For shared paths consume
context's checked `primary_root`, the ordinary source folder derived from the
actual common Git directory in the one-repository/one-project layout. Inspect its
current-copy association; do not derive a root independently or require saved-primary
selection evidence. Resolve `sources.*` in
the current project and `workspace.*` in the primary copy; config location is
not a root. Missing settings block only the part needing them. Do not require
product/specification acceptance just to prepare a copy, or change `ris.yaml`.

Through the selected available tasks adapter freshly verify exactly this task's
identity/type/content, membership, status, blockers and assignee. Check supported
read and claim operations and their actual guarantees; `tasks` v1 alone does not
promise claim. Closed/invalid tasks stop dependent filesystem mutation. For an
explicit human continuation, pass reassignment authority to the adapter's claim
owner; a previous session's claim alone is not a conflict or a reason to ask again.
Otherwise preserve foreign claims. Read-only inspection may return observations
without claiming or creating anything.

For a new assignment resolve actor through the selected task adapter's claim
owner: explicit identity, then applicable configured identity, otherwise a
verified current host-session ID. Forward the exact chosen actor and provenance
to all participants; a delegated recipient uses the caller's assigned actor,
not its own session fallback. No reliable identity means an exact dependent gap,
not an invented OS-user/model/branch identity. On resume, common's explicit-human
continuation rule supplies reassignment authority; fallback/name/lease alone does
not. Verify the existing association and reuse that worktree/branch with changes
and evidence preserved, without requiring proof the old session ended or a new
handoff record. A concrete conflicting writer or unknown association blocks only
the dependent mutation, never authorizes a replacement copy.

For `execution`, retain all existing execution-readiness and active-blocker gates;
the existence of an ID/copy never supplies sufficient accepted task inputs.
For an explicitly selected **pre-execution bug design** action under that purpose,
check the admitted full current report, aligned criteria, accepted behavior/
constraints and authorized material-design scope as the copy-preparation basis.
The pending design's acceptance and the later verified versioned execution basis
are not prerequisites to this copy-only action; they remain required at their
respective design-save and implementation gates. This is not implementation
admission or the feature-preparation blocker exception: retain exact native bug
claim/ownership/children checks and strict active/unresolved blocker refusal.
For `feature-preparation`, require explicit confirmed feature scope/identity,
open own preparation work/claim and permitted actions; accepted documents are
not copy prerequisites and no JSON identity block is required. Through the adapter read every active directed blocker
and establish which requested preparation action it actually prohibits. An
execution-only prerequisite is not automatically a ban on clarifying requirements;
an actual or unresolved blocker of the chosen preparation action stops that action.
Do not remove/ignore edges, override native claim refusal or weaken execution
gates to prepare a copy. Preserve legacy payloads; absent/old/malformed JSON alone
does not block copy preparation or establish ordinary kind.

Use the same native record assignment for this purpose, not an additional
execution claim or preparation task. Purpose comes from the authorized request
and calling contract, not a required tracker metadata field. Beads uses existing
`assignee/in_progress` with the adapter's guards. A checked own preparation
assignment is reused; later execution separately verifies authority, sufficient
inputs and strict execution guards, without a replacement worktree.

An exact native bug uses explicitly advertised ordinary bug reads, complete
children/directed blockers and native claim (Beads `references/bug-execution.md`),
not task-only feature APIs. Keep its native type and same ID/actor/copy association;
do not invent an epic, feature payload or stage children. Report/versioned-basis inputs
may accompany the handoff but do not replace fresh claim/blocker/copy guards.

An explicit ordinary standalone task/child is supported without an epic or
feature payload; its structural parent alone does not establish feature identity.
Use exact ID/links and inspected copy receipts for available facts before asking
for missing association/actor/authority; do not infer them from a title or path.

For a new association propose branch `task/<ID>` and absolute
`workspace.worktrees/<ID>` unless explicit input, project rules or a previously
confirmed association takes priority. Validate the unmodified ID/path/branch:
unsafe or ambiguous values require clarification, not lossy sanitization. A
conventional name alone is not proof of ownership. Require an agreed association
of task, repository, branch and path, accessible prior evidence or explicit
confirmation before reuse; inspect an optional existing witness when supplied.
No new registry or tracker fields are introduced.

Pass repository/current/primary roots, task identity and association evidence,
branch/path, explicit revision or established remote/main rule, permissions,
project constraints and exact optional setup to the base. Explicit adapter choice
wins, then an unambiguous project rule, otherwise Git; installed `wt` does not
select Worktrunk. Apply the base's available read-only tool/path/ref/side-effect
preflight **before claiming or creating**. A missing selected capability blocks
without fallback; do not copy the base's creation or preservation algorithm here.

## Claim-aware composition

Before any creation or environment mutation, confirm an existing own claim or
obtain an explicitly authorized claim of the open task unblocked for its selected
purpose/action through the adapter's supported guarded operation. Pass the exact
purpose/action and inspected blocker-scope evidence to the claim owner; verify
that its admission and post-claim checks support that purpose before relying on
them. With Beads apply its owned `references/claim.md` action-specific branch:
only proved execution-only blockers may permit feature preparation, not unknown
or actual preparation blockers. No purpose-specific support means a dependent
capability gap, not permission to bypass the adapter. If permission/capability is missing, stop
that mutation. Independently reread ownership, in-progress status and blockers
after claim and before each new mutation batch, including retry, setup and
optional evidence writes. Stop on ownership loss or blockers of that action and
report effects; retain strict execution blockers for execution purpose. Any
blocker/content drift needs fresh scope evidence and claim-owner reconciliation
before filesystem progress, even after a successful claim. Preserve a partial
claim when blocked; do not remove edges, force or bypass a native refusal.
Claim/worktree do not isolate shared state or supply CAS/concurrent uniqueness.

Apply the base's preparation/reuse, selected adapter and conditional environment
method to the verified inputs. Keep shared tracker storage, primary task notes,
nested worktrees and other shared mutable resources out of copied setup files;
pass their actual paths and exclusions, including custom/external locations.
Verify the combined result against the task association and permissions, using
the base's actual independent Git observations. Reprepare context with
`project_root` equal to the resulting copy's project directory and the checked
source-folder association; verify paths, applicable rules and selected tracker workspace again.
Require the resulting work copy to be a registered linked worktree, distinct from
the source folder, on its confirmed own branch; reuse that same copy for full,
simple, feature-preparation, bug and document stages. No per-stage copy is needed.
Validate the **entire** selected recipient config through context, including
present unused fields; invalid or inaccessible selected config is an error, not
grounds for defaults. Compare operation/recipient-relevant settings: project and
tracker identity/workspace, applicable rules, checked primary and used shared
paths, plus other sources/roles only when that recipient needs them. A valid
unused difference (for example `sources.product`) alone does not block preparation.
A different tracker or used shared path blocks the dependent handoff even when
the Git copy exists; identify the exact difference and retain independent results.
A missing required setting blocks its dependent part. Do not copy/substitute a
config, supplement non-defaulted fields, or initialize another tracker. Context's
two workspace leaf defaults apply even in a selected valid config. Shared tracker access
must use the confirmed project workspace, not an ambient new database in the copy.

## Handoff, optional evidence and stop

Use the same ID/path/branch on resume and after title/metadata/slug changes. Keep
existing document/user changes; do not rename, create a draft store or second
publication copy, or replay create/setup because a journal is absent. The base
continues to own preservation, hooks/setup and confirmation-first partial recovery.

Return the base's complete copy/environment result plus task ID, actor, purpose,
the selected action and its blocker interpretation, fresh
claim/status/blocker observations, current and primary project roots, confirmed
tracker workspace, config provenance and re-resolved rules/shared paths. Include
association evidence as exact forwarded facts or an accessible locator (unknown
association is an explicit dependent gap),
checked Git source-folder association, actual path/branch/HEAD, new-copy pinned base or n/a on
reuse, index/staged/unstaged/untracked/operation state, tool/version, permissions,
checks/limits and effects. Report copy and environment verdicts separately;
unrequested setup is not proof of environment readiness. This handoff must be
usable without chat history and does not establish implementation readiness.
Apply common recoverable-result facts, including saved/accepted/publication
channels and unfinished remainder. A receiver must freshly check rights, claim,
blockers and operation-specific protection; the witness/lease is not a live gate.

Direct invocation and full-flow preparation do not require creating or reading
`worktree.md`, `execution.md` or an equivalent file/Beads transition journal.
Return the compact checked handoff, forwarding response-only association facts to
the recipient explicitly. An old supplied witness is a hint to verify, not an
authority or prerequisite. Preserve existing notes; do not migrate them.
For nonstandard association, non-idempotent setup, remaining processes or ambiguous
partial effects, retain a compact addressable result in an already authorized
channel before a dependent irreversible action. If it cannot be saved/recovered,
block that action with the exact missing input, not merely "missing journal".
Save optional evidence only at an authorized address: inspect existing content,
preserve history/unrelated text, check scope/concurrency and verify read-back;
otherwise return it unsaved. No registry or new mandatory format is introduced.

For incomplete execution return the cause's `blocked|conflict|error` and enumerate
actual claim, branch/copy, fetched refs and completed
setup actions, failed/missing context or evidence, and exact safe continuation.
Retain effects: no implicit claim release, rollback, removal or blind recreation.
Retry rereads task, copy and setup before further effects. Stop at the checked
handoff; do not prepare a technical plan, implement, review, publish, close tasks
or containers, or name/select/start a next lifecycle skill.
