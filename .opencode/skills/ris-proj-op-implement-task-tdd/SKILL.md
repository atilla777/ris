# Implement one claimed project task through TDD

For feature/child execution apply installed specify-feature's owned
`references/stage-prerequisites.md` before dependent implementation: inspect actual
parent-feature required contracts/results and native blockers, not just child
edges. Unknown evidence blocks dependent action. Kind is not inferred from
membership; ordinary/bug contracts, TDD, claim and native refusal remain unchanged.

Own the project's checked change and handoff. Load/apply `ris-proj-lib-common` and its
applicable resources, `ris-proj-op-resolve-context` for rules/specs/adapter and shared task paths,
and `ris-port-op-implement-change` with required `implementation_mode: tdd` for code/test
work. Before documentation synchronization,
load/apply `ris-proj-op-update-documentation`. Check actual dependency availability and
results, not just their names. Direct execution needs no configured agent role.

Establish exact task ID/project, actor, authorized code/test/docs scope, current
working copy, sufficient accepted technical inputs, and optional
review findings from the request, project and available evidence; ask only for
missing material decisions. Through the selected available adapter freshly read
task identity/content, membership, blockers and claim. Check its explicitly
supported claim operation: `tasks` v1 alone does not promise it. Confirm own
claim or obtain an authorized open/unblocked assignment before file changes;
explicit human continuation uses common's rule and the adapter's guarded
reassignment without another takeover question. Otherwise preserve foreign claims.
Verify ownership/state/blockers after.
Recheck ownership on resumption and before new mutation batches; stop on loss or
new blockers, preserving partial work. Verify the supplied current copy's project/
repository, actual revision/state and suitability without altering existing work.
Read `references/current-copy.md` from **this installed folder** before any
Git-project mutations or shared-path
access. Missing/conflicting inputs block that part. Use the provided suitable copy;
do not create/repair/switch/reset it or load preparation skills/worktree adapters.

For feature-linked work consume published requirements, sufficient design and
their checked independently sufficient basis from admission under common's
`published-inputs.md`; restore only missing/invalidated facts by exact ID/links.
Do not repeat unchanged derivation/decision history. Compare affected content/
contracts with current code when code, target or evidence changes; labels alone
do not prove applicability. Missing substantive inputs block dependent edits;
legacy JSON alone does not. Preserve history/refs without migration or repinning;
material departures return to their owner. Saved prepare policy is consumable,
never originated by implementation or treated as execution authority. Standalone
work needs its own accepted constraints, not an invented feature. Old plans are optional context;
their absence or staleness creates no planning stage or approval gate. Confirm actual
feature linkage: structural parent alone does not imply a feature. Standalone
children need their own scope/criteria/refs/seams, not copied global AC. Simple
accepted constraints need no ceremonial design file; material design does.
For an actual feature child read the confirmed feature parent's actual accepted
documents/decisions using its exact ID and checked sources, then restrict implementation to the child's
own criteria/refs/contracts. Do not expect a feature payload in every child or
replace its contract with the parent's complete acceptance scope.

An exact native bug uses the adapter's ordinary typed reads/claim and its full
current report (or exact published file), aligned criteria, accepted constraints/
decisions and reproducible versioned execution basis. No feature payload
or formal spec/design pair is required for a sufficient report; material technical
choices still need separate design acceptance. Retrieve the full used historical
fields through the adapter via project/tracker + bug ID + exact record version and
used immutable Git source/decision locators. Missing/incomplete history blocks
dependent changes; no full notes snapshot or copied text handoff is required.
Preserve legacy snapshots as usable historical inputs. Compare current report/criteria/decisions and
code applicability before changes/resume, and identify that basis in implementation
and check evidence. Material drift requires targeted reassessment of affected
change/review/evidence before dependent edits. Confirm current-input sufficiency
and a viable approach in current code, without saved plan or omission-decision.
Pass original divergence, success and
affected-regression criteria to the base without tuning expectations to the bug.

Pass verified inputs, constraints and required TDD mode to `ris-port-op-implement-change`;
actually apply its method, test-first cycles and criterion/test checks.
Do not duplicate the loop here or waive it for convenience. Text-only work belongs
to its document operation; associated docs and behavior-preserving refactors use
the base's applicable checks without artificial RED.

Apply `ris-proj-op-update-documentation` to the affected **authorized** documents (or
record a justified no-change result). Supply actual implementation evidence and
whether the tree is pre-integration; future architecture must not be presented as
current before integration. Product writes need separate explicit permission.
Check the combined code/tests/docs diff against task criteria and accepted
contracts. Return the checked change without a saved implementation report or
replacement journal; do not distribute its fields into review, Beads or new files.
No saved author RED/GREEN chronology is required for review/recovery. Missing
history is not proven TDD; a known violation must not be hidden. Independent review
checks the final result and applicable current checks, not author process history.
Do not write tracker content/evidence unless separately authorized through the
adapter's supported concurrency guarantees.

Return status `ok|blocked|conflict|error`, ID/claim/copy, scope and input versions, final snapshot identity,
criteria/checks/docs results and remaining needs. Local
choices do not reopen global design; material departures return bounded impact
and decision needs, with dependent changes stopped. Stop at the checked change;
no independent approval, commit/push, task/container closure or next-skill launch.
