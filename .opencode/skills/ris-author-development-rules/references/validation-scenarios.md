# Author validation scenarios

For maintainers validating this source, not mandatory on normal invocation.
Execute with installed dependencies outside the source repository. Record
package/resource digests, environment/model, permissions, actual dialogue,
candidate/decision and file bytes before/after. Fixture authority is test
evidence, never real approval of a user's other project. Inspect calls and
effects; structural checks or an agent's success sentence alone do not suffice.

| Case | Inputs and expected observation |
|---|---|
| Create | Small Rails web project, no product/tracker/CI, default rules path; actual base/profile and scoped OKF operation, justified tool/practice minimum, show candidate and zero writes before acceptance; accept exact version, inspect typed concepts/root navigation/decision/provenance. No architecture area or tooling configs created. |
| Update/worktree | Existing DragonRuby game in different configured path and real Git worktree. Replace one test policy only; preserve accepted style/tools, publication process, neighboring architecture and extension fields; pure/runtime/target distinctions, unknown SDK limitations. Accept exact delta and verify only current-copy paths change. |
| Odin | Engineering proposal supports architecture's allocator/lifetime constraints using real compiler/test options or visible compatibility deferral; no invented formatter, graphics library or package manager. |
| Related conflict | Proposed version/tool practice conflicts with architecture. Show needed adjacent decision; no automatic architecture-author call/write or overall-consistency claim. Explicitly accepted limited scope may retain visible dependency. |
| No acceptance | Decline/proposal-only: zero normative/index/evidence writes. Interview answers do not grant final approval. |
| Stale baseline | Change a target/index/related rule after candidate and accept the old version: reread detects conflict, preserves foreign bytes and blocks dependent save. |
| Partial | Fail a later accepted write after an earlier succeeds: inspect actual state and report saved/unsaved scope, no blind retry or false completion. |
| Format | Markdown/0.1/future/versionless or 0.2 with unconverted target: no hidden migration; block dependent save when conversion changes storage protocol/beyond scope. Valid scoped target with unrelated invalid architecture may succeed with scope-limited checks, no repair/full-bundle claim. |
| Missing | Missing update input/boundary or required base/context/common/OKF resource blocks dependent result, no silent create/copied replacement. |
| Installed independence | One applicable profile only, no tracker/specs wrapper/architecture author. Remove/change installed materials after save: accepted project norms remain byte-identical and independently usable. |
| Selection | English/Russian project engineering-rule create/bounded update select wrapper; portable text-only, audit, CI setup, architecture norms, feature design, library extraction, impact and irrelevant requests retain their owners. |

The shared example rules bundle belongs to separate packaging work; this skill
does not require it or install it as the project's normative layer.
