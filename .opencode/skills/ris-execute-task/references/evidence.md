# Execution evidence and recovery boundary

Read before the first handoff/report write and when previous or partial execution
is found. Resolve resources from the installed skill; report paths come from
checked project context and confirmed ID, not this installation directory.

## Preserve identified observations

Use the authorized `workspace.tasks/<ID>/execution.md` by default; explicit/project
addresses win. Read existing content first and append a dated run/round entry or
preserve it as explicit history. Do not overwrite earlier findings or provenance.
Keep enough information for another session to inspect reality without this chat:

- Run identity/time, exact ID/title, actor and task/actor/execution association;
  project/current/primary roots, config source and resolved output addresses.
- Requirements/design versions and acceptance addresses; applicable rule/package
  versions and material uncommitted changes to those inputs.
- Each standalone operation's configured role, actual agent invocation/context ID,
  selected owner, permissions, input versions, output address, returned status,
  inspected evidence and actual effects. Mark unavailable provenance as a gap.
- Copy branch/path/base and preservation evidence; claim actor and fresh blockers.
- Plan, implementation and review addresses and their history. For each candidate
  identify baseline commit and complete task snapshot (including additions,
  deletions and modes), checks and independent review applicability. Follow the
  review/publication owners' snapshot contract; a HEAD commit alone is insufficient
  for dirty work. Record exclusions without losing foreign changes.
- Review round/finding IDs, severity, disposition, reviewer independence and
  progress facts. Keep authors of all repairs distinct from independent reviewer.
- Actual Git remote/primary ref/integrated commit, snapshot checks/reassessment,
  push result and independent remote read-back address/revision.
- Separately: criterion/composition verification, authorized write window scope
  and source of its guarantee, persisted result, actual closure read-back; tracker
  remote/outgoing authorization, publication window, pushed snapshot and independent
  read-back. Do not record a local lock as protection against remote writers.
- Confirmed partial effects, uncertainty, first remaining operation, exact
  prerequisite/decision for it, and fresh next recommendation without a claim.

An artifact/flag is not authority that a stage is done. Preserve actual receipt
addresses and versions; inspect files/remote reads where available, rather than
trusting narrative. Missing output permission means an unsaved report and a blocked
dependent persistence claim, not a hidden write. This is evidence, not a scheduler.

## Fresh-run-only recovery behavior

Full resume belongs to the next delivery. If previous effects, own unfinished work
or a partial run exist, perform bounded **read-only reconciliation** with the
corresponding owners: current task/claim/composition/blockers, actual copy/index,
input versions, review snapshot and remote facts. Preserve identity, known commit,
closed status and confirmed publications. Do not treat missing local notes as
permission to start afresh: inspect tracker/Git/available reports to recover facts.
Never reopen a closed ID, reclaim foreign work or select a new target instead.

Return `blocked` for unsupported recovery with the proven effects and first
unfinished or inapplicable operation. Changed inputs may invalidate plan/checks;
changed snapshots invalidate affected checks/review. A confirmed Git publication
survives closure/Dolt failure. An ambiguous push needs independent remote inspection
before any proposed retry. If evidence cannot distinguish fresh work from a
previous effect, return `conflict` and the necessary diagnostic/decision.

Do not replay claim/preparation, implementation, push or closure based on a local
stage marker; do not declare AC-010 or the whole feature delivered. A report can
describe a safe owner-specific remaining operation, but this skill version does
not automatically execute a resumed route. Direct component operations retain
their contracts and can be separately requested with these factual inputs.
