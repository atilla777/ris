# RIS · ОСНОВНОЕ

### 🧭 ГДЕ МЫ

**`/risp-status [ID]`** — план проекта (или поддерева ID), блокировки и одна рекомендация.

**`/risp-next <ID>`** — следующий шаг для выбранной работы.

Оба запроса read-only. Status сначала рассматривает начатую работу в своей области,
даже чужую; рекомендация не разрешает перехват задачи.

---

### 🧩 ПРОРАБОТАТЬ ФИЧУ (ПОДГОТОВИТЬ ЗАДАЧИ)

**`/risp-prepare-feature <ID или контекст>`** — ранний учёт выбранной фичи,
одна безопасная копия и диалог требований/дизайна, достаточное прямое/унаследованное/
смешанное либо допустимое policy-основание обеих областей,
ревью/публикация входов и проверенная декомпозиция с публикацией трекера.
Один авторский контекст, только новые существенные вопросы (связанный блок допустим),
короткая достаточная spec/design. Draft review условен, final independent обязателен.
Resume делает остаток без нового readiness checklist и повторных confirmed pushes.

Prepare по умолчанию принимает требования/дизайн автоматически после содержательных
ответов (`workflows.prepare_feature.auto_accept: false` сохраняет ручной порядок).
Явная просьба согласовать возвращает подтверждение только названным областям;
прямые этапы не получают auto от config. Полные auto-тексты — в документах, итог краткий со ссылками.

**Или отдельными этапами:**

- `/risp-status <ID эпика>` — существующие кандидаты нужного этапа и параллельной работы (read-only).
- `/risp-specify-feature` — согласовать требования.
- `/risp-design-feature` — согласовать дизайн.

Пустой эпик? `/risp-roadmap` планирует эпики и предварительные фичи (по умолчанию
ближайший этап; также epic-only/all). Один эпик MVP допустим. Все заблокированы —
диагностика предпосылок, не новые фичи. Подготовка сохраняет предварительный ID.

**`/risp-decompose-feature <ID>`** — самостоятельно получить/проверить задачи по
принятым опубликованным входам; уже входит в полный prepare. Без реализации.

### ⚙️ ВЫПОЛНИТЬ ОЧЕРЕДНУЮ ПОДГОТОВЛЕННУЮ ЗАДАЧУ

**`/risp-run-task <ID>`** — реализовать, проверить, независимо отревьюить,
опубликовать Git, затем отдельно завершить задачу и опубликовать трекер.

Без ID — сначала подтверждённая незавершённая работа текущего исполнителя (actor),
затем готовая задача: выбор может отличаться от status. Если своя выбранная работа
заблокирована, сценарий остановится на ней. С ID цель фиксирована; контейнер
не подменяется ребёнком, многозадачный контейнер не исполняется как leaf-задача.

**`/risp-run-simple-task <поручение или ID>`** — Fast: одна небольшая ограниченная
проверяемая задача/идея; подходящий естественный запрос выбирает тот же маршрут.
Код/config/docs/tools/локальные файлы допустимы; не изменение продуктовой логики,
архитектуры/существенного контракта, координируемые результаты или широкие/неясные
последствия. Пустой запрос спрашивает о работе. Один основной агент, default ноль
субагентов; самопроверка/TDD сохраняются. Ревью — по явному запросу, mandatory target
policy или конкретному существенному риску, не из-за кода/Git. Versioned — своя
ветка/worktree, local-only — actual targets без фиктивного Git, mixed проверяет оба
канала. Отдельные tracker close/publication при учёте (Beads в RIS обязателен);
подходящие предки закрываются inline без обязательного субагента.

*Выбирайте весь сценарий ИЛИ его отдельные этапы — не оба варианта.*
