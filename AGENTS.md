# RIS — инструкции агенту

Для автономной работы с явно выбранным OKF-бандлом используй `ris-port-op-manage-okf-bundle`; для OKF-операции в выбранном RIS-проекте — `ris-proj-op-manage-okf-bundle` с явными project/root/operation/scope. Обычные Markdown-спецификации не обрабатываются как OKF автоматически.

Перед работой прочитай [README.md](README.md) и применяй [правила разработки](docs/rules/development.md) целиком: они определяют согласование задачи, очередь Beads, локальные заметки, проверки, ревью и публикацию Git и Dolt. Не считай планы уже реализованными функциями. Для проектных путей RIS используй корневой [ris.yaml](ris.yaml); расположение конфигурации относительно этого файла — корень проекта.

В этом проекте пакет установлен в `.opencode/skills/`; исходные скилы с ресурсами хранятся в `skills/`, команды — в `commands/opencode/`, установка синхронизируется из них. Для автономного скила используй `ris-port-op-author-skill`, для RIS-интеграции — `ris-proj-op-author-skill`; одноимённые команды выбирают контракт явно. Общие правила принадлежат `ris-proj-lib-common`, подготовка настроек — `ris-proj-op-resolve-context`. Полная [карта перехода](docs/skill-command-naming-migration.md) объясняет исторические имена без алиасов. Нормативная спецификация — [docs/concepts/index.md](docs/concepts/index.md), правила репозитория — [docs/rules/index.md](docs/rules/index.md): это отдельные OKF 0.2-бандлы по [профилю корпуса](docs/concepts/knowledge-profile.md). Планы поставок — обычный Markdown в [docs/specs/](docs/specs/README.md). Состояния и зависимости новых задач разработки RIS — в Beads; старые `PLAN-*` в игнорируемой `tasks/` — исторический архив, новые локальные заметки — в игнорируемой `.sdlc/tasks/<подтверждённый ID>/`.
